# 日历视图记录操作（EOS8 视图设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 IDE 的**日历视图**中执行记录与日历操作。
本 skill 为**聚合型**：覆盖切换日期模式（月/周）、
周期变更、新增记录、查看记录、修改记录、
拖动记录条改期、拖拽记录两端伸缩改期共 7 项。
**按用户指定的单项操作执行对应小节即可，不要求每次全跑。**

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认目标日历与操作项 →
打开目标日历视图 → 按操作项走对应小节 → 验证生效。

**作用域铁律**：本 skill 仅适用于视图设计器中打开的
日历视图；若当前 IDE 不在视图设计器或目标日历视图，
立即停止并引导用户先打开，绝不跨设计器操作、不碰无关资源。

**删除红线**：记录条右键菜单中有「删除记录」项——
**严禁点击**；本 skill 不执行任何删除操作。

## When to use

- 用户要在日历某天新增一条日程/记录。
- 用户要查看/修改日历上的某条记录。
- 用户要把某条日程拖到另一天（改期）。
- 用户要调整某条日程的开始/结束日期（伸缩）。
- 用户要切换日历的月/周模式或翻上/下月（周）。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` 且能列出浏览器 →
  **WorkBuddy 模式**：用 mcp__browser__* 工具操作；
  take_snapshot 取可交互元素快照；ref 有时效性，
  页面重渲染后须重取快照；点击前可先对目标元素 focus
  并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`
  （`await tools.browser_*` 可用）→ **Trae 模式**：
  用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **目标日历视图**（必填）：要操作的日历视图名称。
- **要执行的操作**（必填）：用户指定的操作项，可多项；
  未指定的项一律不碰。
- **记录表单内容**（按需）：新增/修改记录时由用户提供
  各字段填写值。
- **目标日期**（按需）：新增、拖动改期、伸缩改期时的
  目标日期/周期。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在日历视图 <视图名> 中执行
<操作项列表>，是否继续？」

### Step 3 — 打开目标日历视图并确认形态

在 IDE 中打开目标日历视图（资源树/视图列表定位并打开；
找不到 → AskUserQuestion 请用户指认，不要乱点）。
快照确认画布为日历形态（月/周网格 + 日期格 + 记录条）。
网格内不显示任何记录条 → 大概率「开始日期」字段未绑定，
日历无法组成日期线，先告知用户，终止本流程
（绑定开始日期属于 `ynu-eos8-view-calendar-settings` 的设置范畴）。

### Step 4 — 按用户指定的操作走对应小节

#### 4.1 切换日期模式（月 / 周）

1. 点击日历**右上角**的日期模式切换，可选**月或周**，
   默认为**月**。
2. **验证**：快照确认网格形态切换（月 = 整月多行网格；
   周 = 单行 7 格）。

#### 4.2 周期变更（翻上/下月、上/下周）

1. 点击日历**顶部日期两侧的左右箭头**，向前/向后变更周期。
2. **验证**：快照确认顶部周期文字与网格日期已更新。

#### 4.3 新增记录

1. 鼠标移动至目标日期**格子的右上角日期数字上**，
   点击显示出的**加号**，打开新增弹框。
2. 弹框中**开始日期与结束日期自动填当前日期**——
   若用户指定的日期不是当天，需在表单中手动改为目标日期。
3. 按用户提供的表单内容填写其余字段，点击保存完成新增。
4. **验证**：快照确认弹框关闭且目标日期格出现新记录条。
5. 加号为 hover 才出现（Vue 条件渲染）：合成事件可能
   不触发渲染，重试两次仍不出现 → 转请用户手动点出
   新增弹框，agent 接手填写。

#### 4.4 查看记录

1. 鼠标移动至**记录条**上（记录条颜色变浅），
   **右键**点击**「查看记录」**，打开查看弹框。
2. 读取弹框中记录内容并向用户汇报，关闭弹框恢复界面
   （只关查看弹框，不碰其他）。
3. **验证**：以弹框中实际读出的字段值为准。
4. 右键菜单呼出失败的降级路线：①重取快照重试右键 →
   ②键盘 ContextMenu 键 → ③hover 看是否出现行内图标
   （日历记录条通常没有行内图标，一般直接跳下一级）→
   ④请用户手动点出菜单。

#### 4.5 修改记录

1. 鼠标移动至**记录条**上（记录条颜色变浅），
   **右键**点击**「修改记录」**，打开修改弹框。
2. 在弹框中按用户要求修改表单字段。
3. 填写表单后点击**保存**完成记录修改。
4. **验证**：快照确认弹框关闭且记录条内容/日期归属
   已更新（改了日期的记录条会移动到新日期格）。
5. 右键菜单降级路线同 4.4。

#### 4.6 拖动记录条改期

1. 在**记录条**上按下鼠标左键并拖动，可改变该记录的
   开始和结束日期。
2. 松开鼠标左键后，记录条移动到目标日期。
3. **注意**：只能拖至**其他日期**，拖至当前日期无效。
4. **验证**：快照确认记录条出现在目标日期格、
   原日期格不再显示。
5. **HTML5 原生拖拽**：自动化合成事件可能无法触发拖拽，
   两次尝试失败 → 转请用户手动拖拽。

#### 4.7 伸缩记录条改起止日期

1. 拖拽**记录条的两端**，可分别调整开始日期/结束日期
   （伸缩日程时长）。
2. **较长的记录会自动排在上面**。
3. **验证**：快照确认记录条覆盖的日期范围已变化。
4. 记录条两端的拖拽把手极小，合成事件两次失败 →
   转请用户手动伸缩。

### Step 5 — 汇报

向用户汇报：执行了哪些操作、生效情况
（新增/修改的记录、记录条所在日期与时长、
日期模式与周期变化）。

## 不变量

1. **作用域铁律**：仅在用户确认的目标日历视图内操作，
   不碰无关资源与其他视图。
2. **删除红线**：右键菜单中的「删除记录」**严禁点击**；
   任何「删除」按钮/图标/菜单项一律不执行，删除类操作
   只写警示、转用户手动。
3. **行动后验证**：每个写操作以日历实际变化为准
   （记录条位置/时长/内容），不以点击成功为准。
4. **失败即停**：同一关键操作两次尝试仍失败 → 转用户
   手动或停止并报告现场，不盲目重试、不绕路。

## Notes / gotchas

- **拖动改期与伸缩改期都是 HTML5 原生拖拽**：
  合成事件无法触发时两次失败即转用户手动。
- **hover 才出现的加号**（新增入口）：Vue 条件渲染
  可能不响应合成事件，重试两次仍不出现转用户手动。
- **右键菜单降级路线**：①重取快照重试 → ②键盘
  ContextMenu 键 → ③hover 看行内图标（日历记录条
  通常没有，直接跳下一级）→ ④请用户手动点出菜单。
- **新增弹框的起止日期自动填当前日期**：
  不是当天的事件需手动改日期。
- **未设置结束日期的记录**：记录条宽度仅一天；
  记录条可跨周（行）、跨月（页）显示。
- **日历不显示记录条**：优先排查「开始日期」字段
  是否绑定——未绑定则日历无法组成日期线
  （去 `ynu-eos8-view-calendar-settings` 配置）。
- **新增/修改弹框是 Ant Design 弹层**：渲染在 body 下，
  定位时在整页快照中找，不要局限在触发元素附近。
- **ref 时效性（Trae）**：拖拽/弹框操作后页面重渲染，
  旧 ref 失效，点击前重新获取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前先 focus 目标元素
  并 sleep 约 2 秒再 click。
- **日期粒度只有月/周两种**：文档未提供日粒度，
  用户要「日视图」时如实告知。
