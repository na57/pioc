# 流程视图记录操作与流程设置（EOS8 视图设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 IDE 的**流程视图**中执行记录操作与流程专属设置。
流程视图显示表单字段之外的流程信息：**当前处理人、当前处理
机构、当前活动名称、当前活动到达时间、发起人、发起机构、
发起时间、流程状态**。

本 skill 为**聚合型**：覆盖**记录操作**（流程发起、批量办理、
终止、挂起、查看流程，共 5 项）与**流程专属设置**（动作设置
默认按钮核对、快速筛选流程字段，共 2 项）。
**按用户指定的单项操作执行对应小节即可，不要求每次全跑。**

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认目标流程视图与操作项
（终止/挂起必须二次确认）→ 打开目标流程视图 → 按操作项走
对应小节 → 验证生效。

**作用域铁律**：本 skill 仅适用于视图设计器中打开的流程
视图；若当前 IDE 不在视图设计器或目标流程视图，立即停止并
引导用户先打开，绝不跨设计器操作、不碰无关资源。

**高风险警示**：**终止、挂起会影响流程实例**——属高风险
非删除操作，Workflow 中必须 AskUserQuestion 二次确认后才执行。

**删除红线**：任何「删除」按钮/图标/菜单项**严禁点击**；
本 skill 不执行任何删除操作。

## When to use

- 用户要在流程视图中发起流程。
- 用户要批量办理多条流程记录。
- 用户要终止/挂起某条流程（高风险，需二次确认）。
- 用户要查看某条记录的流程详情。
- 用户要核对流程视图工具栏/行内默认按钮，或添加流程字段
  快速筛选。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` 且能列出浏览器 →
  **WorkBuddy 模式**：用 mcp__browser__* 工具操作；
  take_snapshot 取可交互元素快照；ref 有时效性，
  页面重渲染后须重取快照；点击前可先对目标元素 focus
  并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`
  （`await tools.browser_*` 可用）→ **Trae 模式**：
  用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **目标流程视图**（必填）：要操作的流程视图名称。
- **要执行的操作**（必填）：用户指定的操作项，可多项；
  未指定的项一律不碰。
- **目标记录**（按需）：终止/挂起/查看流程/办理时由用户
  指定记录（行）。
- **筛选项配置**（按需）：做快速筛选设置时由用户指定要加
  的流程字段。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在流程视图 <视图名> 中执行 <操作项列表>，
是否继续？」

**高风险二次确认（必经）**：操作项含**终止**或**挂起**时，
单独再问一次：「⚠️ 终止/挂起会**直接影响流程实例**
（终止后流程结束、挂起后流程暂停流转），确认对记录
<记录标识> 执行<终止/挂起>？」用户明确确认后才继续；
用户犹豫或拒绝 → 跳过该项，只执行其余确认过的操作。

### Step 3 — 打开目标流程视图并确认

在 IDE 中打开目标流程视图（资源树/视图列表定位并打开；
找不到 → AskUserQuestion 请用户指认，不要乱点）。
快照确认画布为流程视图形态（列表中含流程信息列：
当前处理人、当前活动名称、流程状态等）。

### Step 4 — 按用户指定的操作走对应小节

#### 4.1 流程发起

1. 点击工具栏**「发起流程」**按钮（流程视图工具栏默认
   显示发起流程、批量办理、同意、取消等操作按钮）。
2. 按弹出的发起界面完成流程发起（填写内容由用户提供）。
3. **验证**：快照确认流程已发起，列表中出现新流程记录或
   状态更新。

#### 4.2 批量办理

1. 在列表中**勾选多条待办理记录**。
2. 点击工具栏**「批量办理」**按钮。
3. 按弹出的办理界面完成批量办理。
4. **验证**：快照确认所勾选记录的处理状态已更新
   （当前活动/处理人变化）。

#### 4.3 终止（高风险，须已过 Step 2 二次确认）

1. 定位目标记录行，点击**行内「终止」**操作按钮（行内
   操作默认含查看流程、发起流程、办理、终止、恢复等）。
2. 若有确认弹窗，核对记录无误后确认。
3. **验证**：快照确认该记录**流程状态**变为终止态。

#### 4.4 挂起（高风险，须已过 Step 2 二次确认）

1. 定位目标记录行，点击**行内「挂起」**操作按钮。
2. 若有确认弹窗，核对记录无误后确认。
3. **验证**：快照确认该记录**流程状态**变为挂起态。
   （对应恢复操作为行内「恢复」按钮，仅在用户明确要求
   恢复已挂起流程时执行。）

#### 4.5 查看流程

1. 定位目标记录行，点击**行内「查看流程」**操作按钮，
   打开流程详情/流程图界面。
2. 读取流程信息（当前处理人、当前活动、流程状态、流转
   历史等可见内容）并向用户汇报。
3. 关闭详情界面恢复视图，**只关详情，不碰其他**。

#### 4.6 流程专属设置 — 动作设置默认按钮核对

1. 打开视图设置 → **动作设置**。
2. 核对工具栏默认按钮：发起流程、批量办理、同意、取消；
   行内操作默认按钮：查看流程、发起流程、办理、终止、
   恢复等（以实际界面为准）。
3. 用户要求调整按钮显隐时按用户指定项配置；
   **未指定的按钮一律不碰**。

#### 4.7 流程专属设置 — 快速筛选流程字段

1. 打开视图设置 → **快速筛选**，添加筛选条件。
2. 添加筛选条件时可选**流程相关字段**：当前处理人、
   当前处理机构、当前活动名称、当前活动到达时间、
   发起人、发起机构、发起时间、参与类型、流程状态。
3. 按用户指定的字段添加并保存。
4. **验证**：保存后快照确认筛选区出现对应流程字段筛选项。

> 显示、筛选通用配置、动作设置通用项、高级设置等与表格
> 视图一致的部分 → 引导至 `ynu-eos8-view-list-settings`，
> 本 skill 不重复展开。

### Step 5 — 汇报

向用户汇报：执行了哪些操作、生效情况（发起的流程、批量
办理条数、终止/挂起的记录及其新状态、查看流程读出的信息、
设置项调整结果）。

## 不变量

1. **作用域铁律**：仅在用户确认的目标流程视图内操作，
   不碰无关资源与其他视图。
2. **高风险二次确认**：终止/挂起必须经 AskUserQuestion
   二次确认后才执行；未确认绝不点。
3. **删除红线**：任何「删除」按钮/图标/菜单项**严禁点击**；
   删除类操作只写警示、转用户手动。
4. **行动后验证**：每个写操作以流程状态/列表实际变化为准，
   不以点击成功为准。
5. **失败即停**：同一关键操作两次尝试仍失败 → 转用户
   手动或停止并报告现场，不盲目重试、不绕路。

## Notes / gotchas

- **终止/挂起影响真实流程实例**：这两个操作改变流程的
  运行状态，误操作会造成业务中断——二次确认环节不可省；
  批量场景下逐条核对记录标识。
- **右键菜单 4 级降级路线**（如行内操作需右键呼出菜单时）：
  ①重取快照重试右键 → ②键盘 ContextMenu 键 →
  ③hover 记录行看行内操作图标替代 → ④请用户手动点出菜单，
  agent 接手后续。
- **行内按钮可能 hover 才渲染**：Vue 条件渲染下合成事件
  可能不触发渲染，重试两次仍不出现 → 转用户手动点出。
- **弹框是 Ant Design 弹层**：发起/办理弹框渲染在 body 下，
  定位时在整页快照中找，不要局限在触发按钮附近。
- **ref 时效性（Trae）**：弹框打开、状态变更后页面重渲染，
  旧 ref 失效，点击前重新获取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前先 focus 目标元素
  并 sleep 约 2 秒再 click。
- **设置项中与表格视图一致的部分**（显示、通用筛选、
  高级设置等）不在本 skill 展开，引导
  `ynu-eos8-view-list-settings`。
