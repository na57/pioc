# 看板视图记录操作（EOS8 视图设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 IDE 的**看板视图**中执行记录与列操作。
本 skill 为**聚合型**：覆盖分组列移动（拖拽整列换位置）、
新增记录、查看记录、修改记录、拖动卡片换分组共 5 项。
**按用户指定的单项操作执行对应小节即可，不要求每次全跑。**

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认目标看板与操作项 →
打开目标看板视图 → 按操作项走对应小节 → 验证生效。

**作用域铁律**：本 skill 仅适用于视图设计器中打开的
看板视图；若当前 IDE 不在视图设计器或目标看板视图，
立即停止并引导用户先打开，绝不跨设计器操作、不碰无关资源。

**删除红线**：卡片右键菜单中有「删除记录」项——
**严禁点击**；本 skill 不执行任何删除操作。

## When to use

- 用户要在看板中新增一条记录。
- 用户要查看/修改看板中某条记录。
- 用户要把看板卡片拖拽到其他分组列（换分组）。
- 用户要调整看板分组列的顺序（拖动整列）。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` 且能列出浏览器 →
  **WorkBuddy 模式**：用 mcp__browser__* 工具操作；
  take_snapshot 取可交互元素快照；ref 有时效性，
  页面重渲染后须重取快照；点击前可先对目标元素 focus
  并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`
  （`await tools.browser_*` 可用）→ **Trae 模式**：
  用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **目标看板视图**（必填）：要操作的看板视图名称。
- **要执行的操作**（必填）：用户指定的操作项，可多项；
  未指定的项一律不碰。
- **记录表单内容**（按需）：新增/修改记录时由用户提供
  各字段填写值。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在看板视图 <视图名> 中执行
<操作项列表>，是否继续？」

### Step 3 — 打开目标看板视图并确认

在 IDE 中打开目标看板视图（资源树/视图列表定位并打开；
找不到 → AskUserQuestion 请用户指认，不要乱点）。
快照确认画布为看板形态（多个分组列 + 列内卡片）。
画布为空白页 → 看板未配置分组字段，先告知用户，
终止本流程（配置分组字段不属于本 skill）。

### Step 4 — 按用户指定的操作走对应小节

#### 4.1 分组列移动（拖拽整列换位置）

1. 鼠标移动至**列的标题部分**，按下鼠标可以拖动整列。
2. 松开鼠标左键后，该列会移动到当前位置。
3. 说明：此功能配合设置中「**允许用户拖拽排序**」配置使用，
   可自由调整列顺序；若配置为默认排序，拖拽列不生效。
4. **验证**：松开后快照确认列顺序已变化。

#### 4.2 新增记录

1. 点击行操作按钮**「新增」**，打开新增弹框。
2. 在弹框中按用户提供的表单内容填写各字段。
3. 点击保存完成新增。
4. **验证**：快照确认新增弹框关闭且目标分组列中出现
   新卡片。

#### 4.3 查看记录

1. 鼠标移动至卡片记录上，点击**右上角出现的省略号图标**，
   在展开菜单中点击**「查看记录」**，打开查看弹框。
2. 读取弹框中记录内容并向用户汇报，关闭弹框恢复界面
   （只关查看弹框，不碰其他）。
3. **验证**：以弹框中实际读出的字段值为准。
4. 省略号图标为 hover 才出现（Vue 条件渲染）：合成事件
   可能不触发渲染，重试两次仍不出现 → 转请用户手动点出
   查看弹框，agent 接手读取。

#### 4.4 修改记录

1. 鼠标移动至**卡片记录条**上（记录条颜色变浅），
   **右键**点击**「修改记录」**，打开修改弹框。
2. 在弹框中按用户要求修改表单字段。
3. 填写表单后点击**保存**完成记录修改。
4. **验证**：快照确认弹框关闭且卡片信息已更新。
5. 右键菜单呼出失败的降级路线：①重取快照重试右键 →
   ②键盘 ContextMenu 键 → ③hover 卡片点右上角省略号
   图标替代 → ④请用户手动点出菜单。

#### 4.5 拖动卡片换分组

1. 鼠标移动至**卡片内**，点击左键可以拖动卡片。
2. 拖入其他列后松开鼠标左键，该条记录的**分组字段值
   会修改为所在列的分组列值**。
3. **验证**：快照确认卡片出现在目标列，原列卡片减少；
   必要时可查看记录核实分组字段值已变。
4. **HTML5 原生拖拽**：自动化合成事件可能无法触发拖拽，
   两次尝试失败 → 转请用户手动拖拽。

### Step 5 — 汇报

向用户汇报：执行了哪些操作、生效情况
（新增/修改的记录、卡片所在分组列、列顺序变化）。

## 不变量

1. **作用域铁律**：仅在用户确认的目标看板视图内操作，
   不碰无关资源与其他视图。
2. **删除红线**：右键菜单中的「删除记录」**严禁点击**；
   任何「删除」按钮/图标/菜单项一律不执行，删除类操作
   只写警示、转用户手动。
3. **行动后验证**：每个写操作以看板实际变化为准，
   不以点击成功为准。
4. **失败即停**：同一关键操作两次尝试仍失败 → 转用户
   手动或停止并报告现场，不盲目重试、不绕路。

## Notes / gotchas

- **空白页陷阱**：看板画布空白说明未配置分组字段，
  不是记录操作的失败原因——先让用户配置分组字段。
- **拖拽类操作是 HTML5 原生拖拽**：拖卡片换分组、
  拖列换顺序都依赖原生拖拽事件，合成事件无法触发时
  两次失败即转用户手动。
- **hover 才出现的省略号图标**：Vue 条件渲染可能不响应
  合成事件，重试两次仍不出现转用户手动。
- **右键菜单降级路线**：①重取快照重试 → ②键盘
  ContextMenu 键 → ③hover 查行内图标替代 → ④请用户
  手动点出菜单。
- **新增/修改弹框是 Ant Design 弹层**：渲染在 body 下，
  定位时在整页快照中找，不要局限在触发元素附近。
- **ref 时效性（Trae）**：拖拽/弹框操作后页面重渲染，
  旧 ref 失效，点击前重新获取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前先 focus 目标元素
  并 sleep 约 2 秒再 click。
- **分组合计/无数据分组的显示切换、分组排序配置**
  属于看板设置，不属于本 skill。
