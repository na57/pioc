# 输入输出参数配置（EOS8 服务设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 服务设计器中为**当前打开的逻辑流**配置输入输出
（即参数与返回值）。官方要点：
- 一个逻辑流可定义**多个参数、多个返回值**；
  可类比为 Java 方法的参数与返回值。
- 支持简单类型（String/Int/Float/List 等）、
  **SDO 实体对象**（类型为实体全名，如 `test.img.aproject`）、
  **数组**（类型选好后**勾选「数组」**）作为参数/返回值。
- 参数在图元中绑定传递（如运算逻辑图元的参数配置表）；
  返回值可在**结束图元**中以「表达式」类别赋值
  （如 `projectList.size()` 计算返回数量）。

命名硬规则（文档明确）：
- 符合 Java 命名规范；
- 参数名不能与变量名重复；
- 参数名与返回值名可相同，但相同时类型必须完全相同
  （包括数据类型和是否数组）；
- 返回值默认作为一个变量定义，返回值名不能与变量名重复；
- **`_results` 与 `_context` 被流程引擎内部占用，禁止定义**。

流程概览：确认 IDE 已登录 → AskUserQuestion 确认参数清单 →
作用域确认 → 属性设置创建参数/返回值 → 图元绑定 → 执行验证。

**作用域铁律**：仅操作服务设计器中当前打开的服务编排，
不碰其他设计器与其他服务。

## When to use

- 为逻辑流新增/修改输入参数或返回值。
- 排查「参数传不进来 / 返回值取不到」类问题。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**：
  用 mcp__browser__* 工具操作；take_snapshot 取可交互元素快照，
  ref 有时效性，面板重渲染后须重取快照；点击前可先对目标元素
  focus 并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→
  **Trae 模式**：用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **参数清单**（必填）：每个参数与返回值的
  名称 / 数据类型 / 是否数组 / 用途。
- **实体类型全名**（按需）：SDO 实体参数需实体全名
  （如 `test.img.aproject`），必须与用户确认。

缺参数 → `AskUserQuestion` 询问，不要猜
（类型猜错会运行期异常）。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在服务设计器中为 <服务/流程名> 配置参数：
<参数清单摘要>，是否继续？」同时回告命名硬规则
（尤其 `_results`/`_context` 禁用、参数名不与变量名重复）。

### Step 3 — 打开逻辑流属性设置

1. 确认当前在**服务设计器**且打开的是目标逻辑流。
2. 打开**逻辑流属性设置**，定位参数/返回值定义区。

### Step 4 — 创建参数与返回值

1. 按确认清单逐条新增输入参数与返回值：
   - 简单类型直接选类型（String/Int/Float/List…）；
   - SDO 实体：类型填**实体全名**（如 `test.img.aproject`）；
   - 数组：选好类型后**勾选「数组」**（官方示例：入参 ids 为
     String 勾选数组；返回值 out 为实体类型勾选数组）。
2. ⚠️ 红线：参数定义区的**「删除」图标严禁点击**
   （包括选中已有条目后的误删）。
3. 创建后逐条核对：名称、类型、数组勾选与清单一致。

### Step 5 — 在图元中绑定传参（按需）

1. 在**运算逻辑图元**等图元的参数配置表中，
   为图元的输入输出绑定逻辑流参数/返回值。
2. 返回值需要计算时：在**结束图元**中将该返回值的
   「返回值类别」改为**表达式**，写入表达式
   （如 `projectList.size()` 为 count 赋值）。

### Step 6 — 执行验证

1. 点编辑器左上角执行图标打开执行弹窗，输入参数值执行
   （数组参数形如 `["a","b"]`；实体参数按字段给值）。
2. 需要时开断点调试：核对入参已传入逻辑流、
   返回值已正确赋出；**以实际返回数据为准**。

## 不变量

1. **作用域铁律**：只动当前打开的逻辑流的参数配置。
2. **删除红线**：参数/返回值区的删除图标严禁点击。
3. **命名合规**：`_results`/`_context` 禁用；
   参数名不与变量名重复。
4. **行动后验证**：以执行弹窗/断点中参数与返回值实际读出为准。
5. **失败即停**：属性面板两次定位失败即报告。

## Notes / gotchas

- **类型不匹配必炸**：左值类型不符会运行期抛异常；
  SDO/实体类型必须写**实体全名**，写前与用户确认。
- **数组勾选易漏**：List 类型 ≠ String 勾选数组；
  建参数清单时与用户逐条确认。
- **ref 时效性**：属性弹窗重渲染后旧 ref 失效，操作前重取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：图元内赋值用 `ynu-eos8-flow-variable-assign`；
  脚本中读写参数用 `ynu-eos8-flow-script`（`context.参数名`）。
