# 访问权限（EOS8 服务设计器 + AFCenter 平台，WorkBuddy / Trae 双运行时兼容）

## Overview

为控制用户随意使用逻辑流接口，
创建生成的逻辑流都是**可以受控的**；
用户可以指定只能对某些逻辑流进行访问操作
（官方「访问权限」文档）。

**入口与作用域说明（本 skill 与纯画布 skill 不同）**：
- **开关**在服务设计器内：逻辑流**属性设置弹窗**中
  勾选「访问权限」选择框。
- **权限绑定**在 AFCenter 平台（不在服务设计器内）：
  ① 在当前应用的**资源分组**中创建**功能码资源**
  （资源编码必须粘贴为该逻辑流的功能码）；
  ② 在**角色管理**中对目标角色进行功能码资源授权；
  ③ **刷新浏览器**后权限绑定生效。

官方要点：
- 勾选访问权限后执行逻辑流，返回结果会提示
  当前逻辑流**需要执行权限才能调用**。
- 开启后若无法访问，通常是**资源权限未绑定**所致，
  需按上述 AFCenter 流程补齐。
- 绑定完成后：刷新浏览器 → 执行逻辑流 → 访问成功。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认目标逻辑流与
授权角色 → 作用域确认 → 勾选访问权限 →
AFCenter 创建功能码资源并授权 → 刷新浏览器 →
执行验证。

**作用域铁律**：逻辑流操作仅限**当前打开的服务编排**
的属性设置；AFCenter 资源/角色页面只做
**新增功能码资源与授权**，严禁修改/删除既有资源与授权。

## When to use

- 用户要求某逻辑流/服务接口必须授权后才能调用。
- 用户反馈「开启访问权限后接口 403/无法访问」，
  需要补功能码资源绑定与角色授权。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**：
  用 mcp__browser__* 工具操作；take_snapshot 取可交互元素快照，
  ref 有时效性，画布重渲染后须重取快照；点击前可先对目标元素
  focus 并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→
  **Trae 模式**：用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **目标逻辑流**（必填）：当前打开的服务编排。
- **授权角色**（按需）：AFCenter 角色管理中要授权的角色；
  不明确时向用户确认。
- **功能码**（自动获取）：从逻辑流属性/接口信息中复制。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将给逻辑流 <名称> 开启访问权限，
并在 AFCenter 为角色 <角色> 绑定其功能码资源，
是否继续？」

### Step 3 — 逻辑流属性设置中开启访问权限

1. 打开目标逻辑流的**属性设置弹窗**
  （双击画布空白）。
2. 勾选「访问权限」选择框，确定并保存逻辑流。
3. 可先执行一次验证受控已生效：
   执行弹窗运行，返回结果提示需要执行权限
   （此时**不可访问属预期现象**）。

### Step 4 — AFCenter 创建功能码资源

1. 复制当前逻辑流的**功能码**。
2. 进入 AFCenter 平台当前应用的资源管理，
   在资源分组中**创建功能码资源**。
3. **资源编码必须粘贴为该逻辑流的功能码**
   （完全一致，勿手改大小写/后缀）。
4. 保存资源；不改动同组其他资源。

### Step 5 — 角色管理中授权

1. 进入 AFCenter **角色管理**。
2. 对用户指定的当前角色进行
   **功能码资源授权**（勾选 Step 4 创建的资源）。
3. 保存授权；不取消任何既有授权勾选。

### Step 6 — 刷新浏览器并执行验证

1. **刷新浏览器**获取权限绑定结果。
2. 重新执行逻辑流（左上角执行图标），
   返回结果正常即访问成功。
3. 验证以**逻辑流实际可访问/返回值读出**为准，
   不以勾选与授权操作完成为准。

## 不变量

1. **作用域铁律**：逻辑流只动当前打开服务编排的属性设置；
   AFCenter 页面只新增目标资源与目标角色授权。
2. **删除红线**：任何「删除」按钮/图标/菜单项
   （删资源、删授权、删逻辑流）严禁点击。
3. **行动后验证**：以刷新浏览器后实际执行成功为准。
4. **失败即停**：资源分组/角色找不到时停下询问用户，
   不猜测创建位置。
5. **步骤顺序不可跳**：未绑定资源就反复执行验证
   只会持续 403，属正常，不是故障。

## Notes / gotchas

- **开启 ≠ 立即可用**：勾选访问权限后必须完成
  「功能码资源创建 → 角色授权 → 刷新浏览器」
  三步才能访问；向用户预先说明，避免误判为故障。
- **资源编码一致性**：必须原样粘贴逻辑流功能码；
  这是绑定失败最常见原因。
- **刷新时机**：授权后不刷新浏览器，旧会话仍可能
  无法访问（官方步骤明确要求刷新）。
- **入口在两个系统**：开关在 IDE 服务设计器，
  绑定/授权在 AFCenter 平台；找不到 AFCenter 入口时
  询问用户，不越权翻找。
- **ref 时效性**：IDE 画布与 AFCenter 管理页面
  重渲染后旧 ref 失效，操作前重取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：服务调用方式 `ynu-eos8-flow-quick-start`
  （swagger/postman 调试需带 Authorization 凭证）；
  服务编排 `ynu-eos8-flow-io-params`；
  环境变量 `ynu-eos8-flow-env-vars`。
