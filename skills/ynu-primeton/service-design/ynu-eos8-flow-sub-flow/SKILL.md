# 子流程（EOS8 服务设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 服务设计器中用**逻辑流图元（子逻辑流）**
调用其它逻辑流，实现更大范围的逻辑流组装。官方要点：
- **适用场景**：①某段业务操作在多个流程中重复出现，
  抽成独立逻辑流复用；②复杂流程模块化拆分，
  提高可读性与可维护性。
- 在逻辑流图元中选择子逻辑流后，
  **子逻辑流的输入参数与返回值自动呈现**，
  逐项绑定即可完成传参与结果接收。
- **值类别**三种：
  - **常量**：当前参数值是 String 字符串，
    传递方式**仅支持传值**；
  - **变量**：当前逻辑流中定义的变量参数，
    支持**传值**（需支持序列化或实现 clone）
    与**传引用**（指向同一对象，双方修改互相可见）；
  - **表达式**：符合 Java 规范，可使用已定义变量，
    传递方式同变量。
- **异步调用**：逻辑流属性设置 → 高级选项卡 →
  调用方式选「异步调用」；**返回值会被忽略**；
  会另起线程（或经 JMS）执行；
  按引用传递的变量**不会同步回主线程**。
- **事务传播**：Join（默认，子逻辑流事务加入父逻辑流事务）
  与 Suspend（挂起外部事务，子逻辑流内单独启用一个事务；
  与「接受外部事务传递」参数相关）。

流程概览：确认 IDE 已登录 → AskUserQuestion 确认目标
子逻辑流 → 作用域确认 → 拖入逻辑流图元选择子流程 →
配置入参与返回值 → 保存执行验证。

**作用域铁律**：仅操作服务设计器中当前打开的服务编排，
不碰其他设计器与其他服务；**不修改被调用的子逻辑流本身**。

## When to use

- 主流程中需要调用已有逻辑流完成一段业务。
- 需要把重复业务操作抽为子流程复用。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**：
  用 mcp__browser__* 工具操作；take_snapshot 取可交互元素快照，
  ref 有时效性，画布/弹窗重渲染后须重取快照；点击前可先对
  目标元素 focus 并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→
  **Trae 模式**：用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **目标子逻辑流**（必填）：要调用的逻辑流名称；
  其入参出参须已知（未知先查看该逻辑流属性设置）。
- **传参映射**（必填）：子逻辑流每个入参的
  来源值与值类别/传递方式；返回值接收变量。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在服务设计器中为 <主逻辑流名> 调用子逻辑流
<子流程名>，传参映射：<摘要>，是否继续？」

### Step 3 — 核对子逻辑流入参出参

1. 确认目标子逻辑流已存在且已保存。
2. 核对其入参/返回值的名称与类型
   （与传参映射对齐；类型不一致先与用户确认调整方案）。

### Step 4 — 拖入逻辑流图元并选择子逻辑流

1. 从元素面板将**逻辑流**图元拖入画布目标位置并接入连线；
   程序化拖拽两次失败即转用户手动拖入。
2. 在图元中选择目标子逻辑流；
   选择后其**输入参数与返回值自动呈现**。

### Step 5 — 配置参数传递与返回值接收

1. 逐项为子逻辑流入参绑定值：
   常量（仅传值）/ 变量（传值或传引用）/ 表达式。
2. 为每个返回值绑定接收变量或主流程返回值
   （类型需一致）。
3. 官方示例：主流程实体 `project` 以变量+传引用传入；
   子流程返回值 `isSuccess`(String) 由主流程同名类型
   参数接收。

### Step 6 — 按需设置异步与事务传播（高级）

1. 逻辑流属性设置 → **高级**选项卡：
   调用方式选「异步调用」——
   仅当不需要返回值时使用（返回值会被忽略）。
2. 事务传播方式按需选 Join（默认）或 Suspend；
   改动前向用户说明差异并确认。

### Step 7 — 保存并执行验证

1. 保存主逻辑流。
2. 执行弹窗输入参数执行；断点观察数据流向
   （子流程执行前接收变量为空、执行后被赋值）；
   **以实际返回/落库结果为准**。

## 不变量

1. **作用域铁律**：只动主流程画布；
   不进入被调子逻辑流做任何修改。
2. **删除红线**：任何「删除」按钮/图标严禁点击。
3. **行动后验证**：以断点/执行结果中返回值实际读出为准。
4. **失败即停**：图元选择弹窗两次定位失败即报告。

## Notes / gotchas

- **异步调用返回值会被忽略**：需要返回值就保持同步调用；
  异步下传引用的变量也不会同步回主线程。
- **传值有前提**：变量需支持序列化或实现 clone 接口。
- **Suspend 会挂起外部事务**、在子逻辑流内单独开事务；
  与「接受外部事务传递」参数相关，慎改并向用户确认。
- **值类别必须与子流程参数类型对应**，否则运行期出错。
- **ref 时效性**：图元参数弹窗重渲染后旧 ref 失效，
  操作前重取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：子逻辑流的新建与编排本身走
  `ynu-eos8-flow-quick-start`；传参中的赋值细节用
  `ynu-eos8-flow-variable-assign`。
