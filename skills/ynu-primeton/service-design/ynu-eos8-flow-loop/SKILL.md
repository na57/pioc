# 循环元素（EOS8 服务设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 服务设计器中为**当前打开的逻辑流**
配置**循环图元**。官方要点：
- 循环图元提供类似 Java 的 **for 循环与 while 循环**能力；
  循环体内可添加**任何业务图元**，符合循环条件即执行。
- **遍历集合**：被迭代元素支持实现 Collection 接口的对象、
  数组（对象数组或简单类型数组）、org.w3c.dom.Element
  （循环 Element 即依次循环其子 Element）；
  循环迭代变量可为已定义变量，也可为未定义动态变量。
- **按条件循环**：相当于 while，条件满足一直循环。
  条件两种设置：
  - **简单表达式**：只能一行，**不支持多条件的与/或**；
    左值为可赋值变量或属性（定义的变量、实体属性、
    数组元素）；比较操作符与右值（常量/变量）按业务选择；
  - **Java 表达式**：返回值必须为布尔类型
    （如 `i<orders.length`），可用隐含变量 `context`。
- **循环退出**：相当于 Java 的 break，退出当前循环。
- **跳过当前循环**：相当于 continue；
  当循环中的图元发出连线指向**循环开始图元**或
  **循环结束图元**时，即为跳过当前循环。

流程概览：确认 IDE 已登录 → AskUserQuestion 确认循环方式 →
作用域确认 → 声明集合与迭代变量 → 拖入循环图元配置 →
循环体内编排 → 保存执行验证。

**作用域铁律**：仅操作服务设计器中当前打开的服务编排，
不碰其他设计器与其他服务。

## When to use

- 需要遍历集合/数组逐个处理元素。
- 需要按条件重复执行一段编排（while 场景）。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**：
  用 mcp__browser__* 工具操作；take_snapshot 取可交互元素快照，
  ref 有时效性，画布/弹窗重渲染后须重取快照；点击前可先对
  目标元素 focus 并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→
  **Trae 模式**：用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **循环方式**（必填）：遍历集合 / 按条件循环。
- **遍历集合**：被迭代元素（集合/数组参数名）、
  循环迭代元素（迭代变量名及类型）。
- **条件循环**：条件表达式（简单/Java 表达式），
  **写入前向用户展示确认**；并确认循环内有
  使条件趋于结束的赋值。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在服务设计器中为 <服务/流程名> 配置循环：
<循环方式与关键配置摘要>，是否继续？」

### Step 3 — 声明集合与迭代变量（按需）

在逻辑流属性设置中定义被迭代参数
（如官方示例：入参 `orders`(List)、迭代变量 `order`(String)）
或条件变量（如 `length`(Int)）。
参数区**删除图标严禁点击**。

### Step 4 — 拖入循环图元

从元素面板将**循环**图元拖入画布目标位置并接入连线；
程序化拖拽两次失败即转用户手动拖入。

### Step 5 — 配置循环参数

1. 打开循环开始图元参数设置。
2. **遍历方式勾选「遍历集合」**：
   被迭代元素填集合参数（如 `orders`），
   循环迭代元素填迭代变量（如 `order`）。
3. **遍历方式选「按条件循环」**：
   - 简单表达式：左值（如 `length`）、比较操作符
     （如 小于）、右值（如 `count`）、右值类别（如 变量）；
   - Java 表达式：填 boolean 表达式
     （如 `i<orders.length`，**写入前已向用户展示确认**）。

### Step 6 — 循环体内编排

1. 在循环体内拖入**赋值**等业务图元并连线
   （如循环内为迭代变量/累加变量赋值，
   官方示例：1~count 自然数求和 result）。
2. **防死循环自查**：条件循环必须有使条件
   趋向不满足的赋值操作（如 `length` 递增）；
   没有则停下与用户确认后再继续。

### Step 7 — 保存并执行验证

1. 保存逻辑流。
2. 执行弹窗输入参数执行（如 orders=`["1","2","3"]`、
   count=10 期望 result=55）；
   开断点调试观察迭代变量逐次变化；
   **以实际执行结果为准**。

## 不变量

1. **作用域铁律**：只动当前打开的服务编排画布。
2. **删除红线**：任何「删除」按钮/图标严禁点击。
3. **代码红线**：条件表达式写入编辑器前
   必须先向用户展示并确认。
4. **防死循环**：条件循环缺递进赋值即暂停询问用户。
5. **行动后验证**：以断点中迭代变量/循环结果实际读出为准。
6. **失败即停**：拖拽两次失败转用户手动；
   连续失败即报告。

## Notes / gotchas

- **continue 语义**：循环体内图元连线指向
  循环开始图元（或循环结束图元）即跳过本次循环；
  break 用「循环退出」能力表达。
- **简单表达式不支持多条件与/或**：需要组合条件时
  改用 Java 表达式。
- **遍历集合元素类型**：Collection/数组/Element；
  迭代变量类型尽量与元素类型一致。
- **ref 时效性**：循环配置弹窗重渲染后旧 ref 失效，
  操作前重取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：比较操作符清单见 `ynu-eos8-flow-branch`；
  循环内复杂处理用 `ynu-eos8-flow-script`；
  赋值细节用 `ynu-eos8-flow-variable-assign`。
