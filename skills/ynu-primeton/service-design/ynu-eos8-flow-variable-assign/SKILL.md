# 变量赋值元素（EOS8 服务设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 服务设计器中用**赋值图元**给变量赋值。
官方要点：
- 赋值图元可对**一个或多个**可赋值变量赋值；
  可赋值变量包括：已定义变量、已定义变量属性
  （变量为 SDO DataObject/Java 对象/数据实体时）、
  未定义变量、未定义变量属性。
- **左值**通常为一个可赋值变量；**右值类别**三种：
  - **常量**：右值是常量，赋值方式必须为「传值」
    （如左值为字符串，右值写 `5`，相当于 左值="5"）；
  - **变量**：右值是值对象的名称或引用路径
    （`name`、`name[1]`、`name.0`、`user/age` 等），
    支持「传值」与「传引用」；
  - **表达式**：将单行表达式结果赋给左值；
    Java 表达式可用隐含变量：`context`（逻辑流上下文）、
    `sessionContext`（会话上下文），均实现 IDataContext 接口。
- **传值**：变量需支持序列化或提供 clone；
  **传引用**：左值与右值指向同一对象，任一方修改双方可见。
- 赋值也可用脚本图元完成（见 `ynu-eos8-flow-script`）。

赋值前通常先**声明变量**：逻辑流属性配置 →
变量定义模块 → 右上角**加号**新增
（⚠️ 加号旁的**删除**图标严禁点击）。

流程概览：确认 IDE 已登录 → AskUserQuestion 确认赋值清单 →
作用域确认 → 声明变量 → 拖入赋值图元配置左值/右值 →
保存执行验证。

**作用域铁律**：仅操作服务设计器中当前打开的服务编排，
不碰其他设计器与其他服务。

## When to use

- 在逻辑流中给变量/参数/返回值赋值
  （常量、变量引用、表达式三种场景）。
- 排查「变量值不对 / 赋值报类型错误」类问题。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**：
  用 mcp__browser__* 工具操作；take_snapshot 取可交互元素快照，
  ref 有时效性，画布/弹窗重渲染后须重取快照；点击前可先对
  目标元素 focus 并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→
  **Trae 模式**：用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **变量声明**（按需）：变量名与数据类型；已存在则跳过。
- **赋值清单**（必填）：每条赋值的
  左值 / 右值 / 右值类别 / 赋值方式；
  表达式内容须在写入前向用户展示确认。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在服务设计器中为 <服务/流程名> 的赋值图元
配置：<赋值清单摘要，含表达式全文>，是否继续？」

### Step 3 — 声明变量（按需）

逻辑流属性配置 → 变量定义模块 → 右上角加号新增，
核对名称与类型；**删除图标严禁点击**。

### Step 4 — 拖入赋值图元

从元素面板将**赋值**图元拖入画布目标位置并接入连线；
程序化拖拽若为 HTML5 拖拽常失败，**两次失败即转用户手动拖入**。

### Step 5 — 配置左值与右值

1. 左值选目标变量/属性；右值按确认清单填写：
   - **常量**：直接写值，赋值方式=传值
     （字符串、数字可直接写）；
     日期等用表达式，如 `new Date()`（赋值方式传引用）；
   - **变量**：写变量名或路径（如 `user/age`），
     传值或传引用；
   - **表达式**：写单行 Java 表达式
     （**写入前已向用户展示并确认**）。
2. **空字符串/空对象**：右值类别选「表达式」，
   空字符串输入 `""`，空对象输入 `null`。
3. **SDO 实体**：同数据类型可直接整体赋值；
   对属性赋值用 XPath，如 `User/name` 给 User 的
   name 属性赋值。
4. **数组**：下标方式 `[]` **从 1 开始**
   （`array[1]` 取第一个元素「男」）；
   打点方式 `.` **从 0 开始**（`username.0` 为第一个元素）。
5. 保存赋值配置并保存逻辑流。

### Step 6 — 执行验证

执行弹窗输入参数执行；通过断点/返回值核对变量值，
**以实际读出为准**，不以配置保存成功为准。

## 不变量

1. **作用域铁律**：只动当前打开的服务编排画布。
2. **删除红线**：任何「删除」按钮/图标严禁点击
   （变量区、图元、参数均含）。
3. **代码红线**：表达式内容写入编辑器前
   必须先向用户展示并确认。
4. **行动后验证**：以执行结果中变量实际值为准。
5. **失败即停**：拖拽两次失败转用户手动；
   连续失败即报告。

## Notes / gotchas

- **类型匹配**：左值已定义时，右值须为同类型或其子类型，
  否则运行期抛 ClassCastException；
  未定义变量运行时按右值类型推断赋值。
- **数组下标两套规则易错**：`[]` 从 1 起、
  打点 `.` 从 0 起。
- **List/Array 互赋均为传值**（含 Array→Array）。
- **ref 时效性**：赋值弹窗重渲染后旧 ref 失效，操作前重取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：参数/返回值定义用 `ynu-eos8-flow-io-params`；
  复杂逻辑赋值用脚本图元 `ynu-eos8-flow-script`。
