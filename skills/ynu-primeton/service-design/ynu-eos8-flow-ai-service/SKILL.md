# AI 服务图元（EOS8 服务设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 **服务设计器**中，
**AI 服务图元**封装了 AI 大模型（如 GPT、文心一言等）的
接口调用、参数解析、异常处理等底层逻辑；开发者无需手写
AI 接口调用代码，将图元拖入编排画布，配置消息参数
（role/content）、返回值映射等关键项，即可快速集成
AI 能力（智能问答、文本生成、多轮对话等），
并与流程中其他图元联动（官方「AI服务」文档）。

官方要点：
- **使用前提**：平台已完成 AI 大模型接入
  （参考智能体开发手册 → 模型管理；
  即 AI 中心已配置好大模型）。
- 图元配置：点**选择大模型**下拉框，
  选 AI 中心已配置好的大模型。
- **是否开启流式会话**：控制响应返回方式
  （SSE 流式能力封装）。开启=生成内容逐字/逐句实时推送
  （类似打字机效果）；关闭=生成完成后一次性返回完整结果。
- 逻辑流参数设置：定义变量 `messages`，类型 **List**；
  新增返回值参数 `out`，类型 javaBean，
  class 填 `org.springframework.http.ResponseEntity`。
- 消息参数由**前置脚本图元**构造：
  messages 为 List，元素是含 `role`（发送者身份）
  与 `content`（对话内容）的 map，
  最后 `context.messages = messages` 写入上下文。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认大模型与提示内容 →
作用域确认 → 拖图元并选模型 → 脚本构造 messages →
保存 → 执行验证。

**作用域铁律**：仅操作服务设计器中**当前打开的服务编排**，
不碰其他设计器、其他服务；不执行任何删除类按钮。

## When to use

- 用户想在流程/逻辑流里调用大模型实现智能问答、
  文本生成、多轮对话等 AI 能力。
- 用户描述「流程里接 AI」「让服务回答问题/生成文本」等需求。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**：
  用 mcp__browser__* 工具操作；take_snapshot 取可交互元素快照，
  ref 有时效性，画布重渲染后须重取快照；点击前可先对目标元素
  focus 并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→
  **Trae 模式**：用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **大模型**（必填）：AI 中心已配置的模型，
  从图元下拉框中选择。
- **消息内容**（必填）：发送给大模型的对话内容
  （`message.content`），必要时含用户问题变量。
- **流式会话**（按需）：开启/关闭，默认向用户确认。
- **role**（按需）：默认 `user`；多轮对话时按轮次组织。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在服务设计器当前逻辑流中加入 AI 服务图元，
模型 <模型名>，流式 <开/关>，是否继续？」
若用户要的模型在 AI 中心未配置，提示先完成
模型管理接入，本 skill 不代配置。

### Step 3 — 拖图元并选择大模型

1. 逻辑流画布中拖选 **AI 服务图元**（双击空白面板
   先定义参数更顺，见 Step 4）。
   - 画布拖拽若为 HTML5 拖拽，程序化拖拽常失败：
     **两次失败即转用户手动拖拽**，agent 接手配置。
2. 双击图元打开 AI 服务配置，点选择大模型下拉框，
   选择合适的大模型；按确认结果勾选/不勾选
   「是否开启流式会话」；点确定关闭弹窗。

### Step 4 — 定义逻辑流参数与返回值

双击画布空白打开逻辑流参数设置：
- 定义变量 `messages`，类型 **List**；
- 新增返回值参数 `out`，类型 javaBean，
  class 填 `org.springframework.http.ResponseEntity`；
点确定关闭弹窗。再打开 AI 服务图元设置，
设置入参（messages）与返回值（out）。

### Step 5 — 前置脚本图元构造消息参数

1. 拖选一个**脚本图元**放置在 AI 服务图元**之前**，
   连线：开始 → 脚本 → AI 服务 → 结束。
2. 双击脚本图元，写入消息构造脚本
   （官方示例，写入前必须先向用户展示并确认）：

   ```groovy
   //创建list集合
   def messages = []
   //创建map对象
   def message = [:]
   //消息发送者的身份
   message.role = 'user'
   //与ai对话的内容
   message.content = '你是谁'
   messages.add(message)
   context.messages = messages
   ```

3. `content` 中的提问文案按用户需求替换；
   变量拼接等改动先展示确认。

### Step 6 — 保存与执行验证

1. 完成逻辑流连线并保存。
2. 点击逻辑流编辑器**左上角执行图标**打开执行弹窗，
   点击执行，核对返回结果中的 AI 回答内容。
3. 验证以**AI 回答实际读出**为准，
   不以图元/脚本保存成功为准。

## 不变量

1. **作用域铁律**：只动当前打开的服务编排画布。
2. **删除红线**：任何「删除」按钮/图标/菜单项严禁点击。
3. **代码红线**：脚本/提示文案写入编辑器前必须
   先向用户展示并确认。
4. **行动后验证**：以执行返回的 AI 回答实际读出为准。
5. **失败即停**：拖拽两次失败转用户手动；连续失败即报告。

## Notes / gotchas

- **多轮对话**：messages 是 List，可加多条
  role/content 的 map（如历史 user/assistant 轮次），
  顺序即对话顺序。
- **脚本图元必须在 AI 图元之前**：messages 要在
  AI 图元执行前写入上下文，位置放反会取不到消息。
- **流式开关影响返回形态**：开启=分批实时推送，
  关闭=一次性返回；断点/执行弹窗验证建议先关闭流式。
- **模型未接入**：下拉框找不到模型说明 AI 中心/模型管理
  未完成接入，转用户处理，不代配置。
- **画布拖拽**：元素面板→画布多为 HTML5 拖拽，
  程序化拖拽常失败，两次失败即请用户手动拖入。
- **ref 时效性**：画布/属性弹窗重渲染后旧 ref 失效，
  操作前重取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：REST 图元通用规则 `ynu-eos8-flow-rest`；
  脚本图元细节 `ynu-eos8-flow-script`；
  环境变量 `ynu-eos8-flow-env-vars`。
