# 发送消息图元（EOS8 服务设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 **服务设计器**的常用图元中，
**发送消息图元**可快速发送消息到指定目标，
支持多种发送类型与发送目标方式（官方「常用图元」文档）。

配置参数：
- **显示名称**：图元在画布上的展示名称。
- **数据来源**：输入数据实体对象；**来源类型**：其结构类型。
- **发送类型**：可选**邮件、短信、站内信**。
- **标题**：发送站内信或邮件的标题内容。
- **发送内容**：站内信或邮件的内容，
  **支持 el 表达式**，如 `您有一条学生姓名为${name}的审批信息待查看`，
  `${name}` 默认从数据来源实体字段中匹配取值。
- **模板 code**：连接器短信消息配置中的短信模版 code。
- **模版变量**：短信模版变量值，匹配数据来源实体字段值。
- **发送目标**：可选**人员、机构、平台角色、应用角色、复合**。
- **发送方式**：可选指定用户，或数据来源中的实体字段值。
- **发送策略**：直接发送，或定时发送
  （固定时间，或指定数据来源的实体字段值）。
- **返回值**：消息发送后的返回值。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认消息类型与目标 →
作用域确认 → 定义参数并拖图元 → 配置图元 →
保存 → 执行验证。

**作用域铁律**：仅操作服务设计器中**当前打开的服务编排**，
不碰其他设计器、其他服务；不执行任何删除类按钮。

## When to use

- 用户想在流程/逻辑流里发送站内信、邮件或短信通知。
- 用户描述「审批后通知某人」「流程里发提醒消息」等编排需求。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**：
  用 mcp__browser__* 工具操作；take_snapshot 取可交互元素快照，
  ref 有时效性，画布重渲染后须重取快照；点击前可先对目标元素
  focus 并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→
  **Trae 模式**：用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **发送类型**（必填）：站内信/邮件/短信。
- **发送目标**（必填）：人员/机构/平台角色/应用角色/复合，
  以及具体用户或来源实体字段。
- **标题与内容**（站内信/邮件必填）：内容可含 `${字段}` el 表达式。
- **数据来源**（按需）：承载目标与模板变量的实体入参。
- **短信模板 code**（发短信必填）：平台连接器中配置的模板 code。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在服务设计器当前逻辑流中加入发送消息图元：
类型 <站内信/邮件/短信>，发送目标 <目标>，是否继续？」

### Step 3 — 定义参数并拖图元

1. 双击画布空白打开逻辑流属性设置，定义实体类型入参
  （如 `student` 实体）与返回值（如 `out`，List 类型）。
2. 从元素面板把**发送消息图元**拖入画布（官方示例中该图元
   常放在发起流程等图元之后），拉线连接形成
   开始 → 业务图元 → 发送消息 → 结束。
   - 画布拖拽若为 HTML5 拖拽，程序化拖拽常失败：
     **两次失败即转用户手动拖拽**，agent 接手配置。

### Step 4 — 配置图元（双击图元打开属性弹窗）

1. 数据来源：选逻辑流入参实体；来源类型自动带出。
2. 发送类型：按用户确认的选择（站内信/邮件/短信）。
3. 站内信/邮件：录入标题与发送内容；内容中的 `${字段}`
   el 表达式默认从数据来源实体字段取值。
4. 短信：模板 code 填平台连接器中配置的短信模板 code；
   模版变量选数据来源实体字段。
5. 发送目标与发送方式：选目标类别；发送方式选
   「指定」用户或数据来源实体字段值。
6. 发送策略：直接发送或定时发送。
7. 返回值：填逻辑流返回值（如 `out`）。

### Step 5 — 保存与执行验证

1. 保存逻辑流。
2. ⚠️ **执行调试会真实发送消息**（站内信/邮件/短信发给
   指定目标）：执行前必须向用户复述发送对象与内容并确认。
3. 点击逻辑流编辑器**左上角执行图标**打开执行弹窗，
   输入参数后执行，核对返回值。
4. 验证以**返回值实际读出**为准（实际是否收到消息以用户
   侧反馈为准）；不以图元配置成功为准。

## 不变量

1. **作用域铁律**：只动当前打开的服务编排画布。
2. **删除红线**：任何「删除」按钮/图标/菜单项严禁点击。
3. **发送需确认**：执行调试会真实发消息，执行前必须用户确认。
4. **行动后验证**：以执行弹窗返回值实际读出为准。
5. **失败即停**：拖拽两次失败转用户手动；连续失败即报告。

## Notes / gotchas

- **代码红线**：标题/发送内容/模板 code 等文本写入编辑器前，
  必须先向用户展示并确认（尤其含 el 表达式的文案）。
- **el 表达式取值范围**：`${字段}` 默认从**数据来源实体字段**
  匹配，字段名要与实体属性一致，否则渲染为空。
- **短信依赖连接器**：模板 code 必须是平台连接器短信服务中
  已配置的模板，配错会发送失败。
- **发送方式选「实体字段值」时**：确认数据来源里确有承载
  接收人的字段（如手机号/人员编码）。
- **画布拖拽**：元素面板→画布多为 HTML5 拖拽，
  程序化拖拽常失败，两次失败即请用户手动拖入。
- **ref 时效性**：画布/属性弹窗重渲染后旧 ref 失效，
  操作前重取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：数据库操作图元 `ynu-eos8-flow-db-elements`；
  发起流程图元与数据库图元同属常用图元
  （见 `ynu-eos8-flow-db-elements` 的发起流程说明）；
  调远程接口 `ynu-eos8-flow-rest`。
