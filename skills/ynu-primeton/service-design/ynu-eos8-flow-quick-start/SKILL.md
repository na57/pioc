# 服务编排快速上手（EOS8 服务设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 **服务设计器**中从零编排一个逻辑流服务。
官方要点：
- 一个逻辑流至少包含**「开始」和「结束」两个图元**。
- 常见图元：开始、结束、赋值、循环、逻辑流（子流程）、
  运算逻辑、REST 服务、EOS 服务、注释图元等。
- 除结束图元外，每个图元都可发出若干根连线连接其他图元；
  连线上可设置转移条件，条件满足时流转到该连线指向的图元。
- 逻辑流上下文（数据区）：逻辑流执行时自动创建，包含逻辑流
  参数与变量、当前登录用户 MUO、系统变量与应用系统变量；
  生命周期与逻辑流一致。

**与其他 flow-* skill 的分工**（本 skill 为入口引导）：
- 输入输出参数细节 → `ynu-eos8-flow-io-params`
- 变量声明与赋值图元 → `ynu-eos8-flow-variable-assign`
- 分支/连线条件表达式 → `ynu-eos8-flow-branch`
- 循环图元 → `ynu-eos8-flow-loop`
- 子流程（子逻辑流） → `ynu-eos8-flow-sub-flow`
- 脚本图元 → `ynu-eos8-flow-script`

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认服务名与业务逻辑 →
作用域确认 → 定义入参出参 → 拖图元连线编排 → 保存 → 执行验证。

**作用域铁律**：仅操作服务设计器中**当前打开的服务编排**，
不碰其他设计器、其他服务；不执行任何删除。

## When to use

- 用户想新建一个服务/逻辑流并完成基础编排（开始→业务图元→结束）。
- 用户想走通「编排→保存→运行验证」全流程。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**：
  用 mcp__browser__* 工具操作；take_snapshot 取可交互元素快照，
  ref 有时效性，画布重渲染后须重取快照；点击前可先对目标元素
  focus 并 sleep 约 2 秒，避免 CDP 超时。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→
  **Trae 模式**：用该运行时操作；同样注意快照 ref 时效性，
  每次操作前重取快照。
- 两者都不可用 → 终止并告知用户当前无可用浏览器运行时。

## 参数

- **服务/流程名**（必填）：新建逻辑流的名称（符合 Java 命名规范）。
- **业务逻辑**（必填）：这段编排要做什么（输入 → 处理 → 输出）。
- **入参/出参**（按需）：名称与数据类型，可后补。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在服务设计器中新建逻辑流 <名称>，按以下逻辑编排：
<业务逻辑概述>，是否继续？」

### Step 3 — 新建并打开服务设计器

1. 在目标构件包下新建逻辑流/服务并打开服务设计器画布
   （文档未详述新建入口，以 IDE 资源树新建/右键菜单实际界面为准）。
2. 新画布默认含**开始**与**结束**两个图元。

### Step 4 — 定义参数（简版）

打开逻辑流属性设置，创建输入参数与返回值。
官方示例（价格折扣）：入参 `price`(Float)、返回值 `total`(Float)。
细节与命名硬规则见 `ynu-eos8-flow-io-params`。

### Step 5 — 拖拽图元并连线编排

1. 从元素面板（选用板）把**赋值**等业务图元拖入画布，
   落在开始与结束之间。
2. 从上一图元边缘拉线连接下一图元，形成
   **开始 → 业务图元 → 结束** 链路。
   - 画布拖拽若为 HTML5 拖拽，程序化拖拽常失败：
     **两次失败即转用户手动拖拽**，agent 接手后续配置。
3. 官方示例编排：小于 500 分支赋值 total=price
   （右值类别=变量，赋值方式=传引用）；另一分支
   total=price*0.8（右值类别=表达式）。分支条件配置见
   `ynu-eos8-flow-branch`。

### Step 6 — 保存与运行验证

1. 保存逻辑流。
2. 点击逻辑流编辑器**左上角执行图标**打开执行弹窗；
   在入参配置表输入参数值（如 price=500），点执行，
   核对返回值（total=400）。
3. 验证以**返回值实际读出**为准，不以按钮点击成功为准。
4. 需要观察流转：右键图元「设置断点」→ 左上角「开启调试」→
   执行后在调试信息中查看入参值与逻辑流上下文。

## 不变量

1. **作用域铁律**：只动当前打开的服务编排画布，
   不碰其他设计器与其他服务。
2. **删除红线**：任何「删除」按钮/图标/菜单项
   （删图元、删参数、删服务）严禁点击。
3. **行动后验证**：以执行弹窗返回值实际读出为准。
4. **失败即停**：拖拽两次失败转用户手动；连续失败即报告，不盲目重试。

## Notes / gotchas

- **画布拖拽**：元素面板→画布多为 HTML5 拖拽，程序化拖拽常失败，
  两次失败即请用户手动拖入。
- **ref 时效性**：画布/属性面板重渲染后旧 ref 失效，操作前重取快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **新建入口文档未详述**：以 IDE 实际界面为准，找不到入口时询问用户。
- **其他调试方式**（文档补充，按需转述给用户）：
  每条逻辑流也是一个 POST 类型 REST 接口
  （`/构件包编码.服务名.biz.ext`），可在
  `swagger-ui.html?urls.primaryName=eosservice` 查看并用 postman
  调试（Headers 需带 Authorization 凭证，可从 IDE 请求头复制）；
  页面侧可在视图动作设置新增按钮、动作模块选「执行代码」，
  经代码助手「调用服务」插入 `this.Ajax.post(...)` 调用。
- **衔接**：参数细化 `ynu-eos8-flow-io-params`；条件表达式
  `ynu-eos8-flow-branch`；赋值细节 `ynu-eos8-flow-variable-assign`；
  循环 `ynu-eos8-flow-loop`；子流程 `ynu-eos8-flow-sub-flow`；
  脚本逻辑 `ynu-eos8-flow-script`。
