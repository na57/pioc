# 创建实体——导入创建（EOS8 低代码平台，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 IDE 当前打开的界面中，通过**导入**方式为目标实体集创建实体。
官方提供两种导入方式：
1. **导入 pdm 创建**：直接上传 pdm 文件即可；
2. **导入 Excel 创建**：系统提供 Excel 模板，下载编辑后再上传。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认目标实体集与导入方式 →
资源树右键实体集 → 菜单选【创建实体-导入创建】→ 按方式上传文件 →
验证实体集下出现新实体。

**作用域铁律**：导入目标必须经 `AskUserQuestion` 确认（实体集 + 文件 + 方式）；
pdm/Excel 内容决定生成的实体结构，导入前必须让用户确认文件来源与内容要点。

## When to use

- 用户要「创建实体」「导入实体」「用 pdm 建实体」「用 Excel 批量建实体」。
- 若用户想手绘实体（拖曳到画布），改用 `ynu-eos8-drag-create-entity`；
  若想从数据库表反向生成实体，改用 `ynu-eos8-create-entity-from-datasource`。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **目标实体集**（必填）：资源树「构件包 → 实体 → <实体集>」中的实体集名称
  （树节点只显示名称不显示编码）。
- **导入方式**（必填二选一）：`pdm` 或 `excel`。
- **导入文件**（必填）：本地 pdm/Excel 文件路径。excel 方式若用户还没有文件，
  先走「下载模板」支线（见 Step 5）。

缺任一参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等前置 skill 产出的 IDE 标签页/viewId；
否则列标签页找 URL 含 `/ide/index.html` 的页面；未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认三项：目标实体集、导入方式（pdm / excel）、导入文件路径。
excel 方式且用户无现成文件时，告知流程：先下载模板 → 用户编辑 → 再上传。

### Step 3 — 定位实体集

在左侧资源树展开目标构件包 → 「实体」→ 目标实体集
（Element Plus el-tree，节点只显示名称）。

### Step 4 — 右键实体集打开菜单

1. 右键实体集节点，期待上下文菜单含【创建实体-导入创建】。
2. **右键可能无反应**（合成右键对部分树节点不触发自定义菜单）。
   降级路线：① 重取快照重试一次；② 键盘 ContextMenu 键；
   ③ hover 看操作图标；④ 请用户手动点出菜单后继续。
3. ⚠️ 红线：菜单中任何「删除」项一律不点击。

### Step 5 — 上传文件

**pdm 方式**：
1. 选择导入方式为 pdm（若有方式切换控件）。
2. 触发文件选择控件，用运行时的文件上传能力指定本地文件：
   - Trae 模式：Exec 内文件上传类 browser 工具（如 `browser_upload_file`，若可用）
     指定绝对路径；
   - WorkBuddy 模式：对应的文件上传工具；
   - **上传对话框是 OS 级，工具不可用时**：如实告知用户在该对话框中手动选择文件，
     用户完成后继续（不要反复重试触发上传）。

**excel 方式**：
1. 先点「下载模板」，等待浏览器下载完成（Trae：轮询下载事件/文件系统）。
2. 把模板路径告知用户，请用户编辑好实体定义后提供最终文件路径
   （agent 可协助按用户给的表结构生成 Excel 内容，但内容需用户确认）。
3. 同 pdm 方式上传编辑后的 Excel。

### Step 6 — 提交并验证

1. 点导入/确定按钮提交。
2. **成功验证以资源树为准**：重取快照/DOM，确认目标实体集下出现新实体节点。
3. 有报错（文件格式、必填缺失、名称冲突等）→ 原样报告，不改其他内容。

### Step 7 — 保留会话

保持标签页打开，供后续 skill（生成表 `ynu-eos8-generate-table` 等）复用。

## 不变量

1. **导入前必确认**：实体集、方式、文件三要素经 AskUserQuestion 确认。
2. **文件内容用户负责**：pdm/Excel 内容决定实体结构，agent 不得擅自编造实体定义。
3. **行动后验证**：成功以资源树出现新实体为准，不以弹窗关闭为准。
4. **失败即停**：上传失败不无限重试，转为用户手动协助。
5. **删除红线**：任何「删除」入口一律不点击、不尝试。

## Notes / gotchas

- **OS 级文件对话框是本 skill 最大风险点**：浏览器自动化对系统文件选择框
  无能为力，优先用运行时 upload 工具，不行立即转用户手动。
- **右键菜单降级路线**见 Step 4；不要反复硬试。
- **树技术栈**：Element Plus el-tree，节点只显示名称。
- **ref 时效性（Trae）**：弹窗/树刷新后旧 ref 失效，重新快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **持久化实体提醒**：导入生成的持久化实体需要数据库表支撑，
  完成后可引导用户执行 `ynu-eos8-generate-table`。
