# 生成表 / 创建表（EOS8 低代码平台，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 IDE 中把实体定义落成数据库表。平台会根据实体（集）
生成 `CREATE TABLE` SQL，**用户可修改 SQL**，并**可选择数据源**执行。

两种粒度：
1. **整体生成表**：右键**实体集** → 生成表（按实体集生成 SQL）；
2. **单独生成表**：右键**实体** → 生成表（按所选实体生成 SQL）。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认粒度与数据源 → 右键目标 →
菜单「生成表」→ 展示/核对 SQL → 选数据源 → 执行 → 验证。

**作用域铁律**：生成表会在目标数据库**真实建表**（有副作用）。
执行前必须用 `AskUserQuestion` 向用户确认：粒度（实体集/单个实体）、
目标数据源、以及 SQL 关键内容（表名、字段）。确认前绝不点执行。

## When to use

- 用户说「生成表」「建表」「落库」「把实体生成表」。
- 持久化实体**必须**有对应数据库表——拖曳创建持久化实体后
  （`ynu-eos8-drag-create-entity`）通常接本 skill。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **粒度**（必填）：`实体集整体` 或 `单个实体`（需指定实体名）。
- **数据源**（必填）：执行 SQL 的目标数据源，从平台数据源列表中选择。
- **SQL**（可选）：用户如指定了表名前缀/字段调整，在确认环节合并进 SQL
  再执行；未指定则用平台生成的默认 SQL 并在确认时向用户展示要点。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

1. 在资源树定位目标（实体集或实体），确认存在。
2. **必须**确认：「将为 <实体集/实体> 生成表，目标数据源 <名称>，
   表名 <…>，是否继续？」执行按钮在确认前不碰。

### Step 3 — 右键目标打开菜单

1. 粒度为整体 → 右键**实体集**节点；单独 → 右键**实体**节点
   （实体通常在实体设计器画布内或资源树实体集下，按实际界面定位）。
2. **右键可能无反应**（合成右键对部分节点不触发自定义菜单）。
   降级路线：① 重取快照重试一次；② 键盘 ContextMenu 键；
   ③ hover 看操作图标；④ 请用户手动点出菜单后继续。
3. ⚠️ 红线：菜单中任何「删除」项一律不点击。

### Step 4 — 菜单选「生成表」，进入 SQL 界面

- 菜单项在快照/DOM 中定位「生成表」点击；
  无独立节点时用键盘 `ArrowDown` + `Enter`。
- 等待 SQL 生成界面出现（Trae：`browser_wait_for` 等特征文本；
  WorkBuddy：轮询 DOM）。

### Step 5 — 核对 SQL 与数据源

1. 读取生成的 SQL，抽取表名与主要字段，向用户汇报。
2. 用户有调整要求 → 在 SQL 编辑区内修改（Trae：填入编辑框后重取快照确认；
   WorkBuddy：click + type 逐段修改）。
3. 在数据源配置处选择用户确认过的数据源
   （下拉/选择器操作后重取快照确认选中值）。

### Step 6 — 执行并验证

1. 点执行/确定按钮。
2. 验证执行结果：
   - 界面出现成功提示 → 再以资源树/实体状态佐证；
   - 有报错（表已存在、SQL 语法、数据源连接失败）→ 原样报告，
     **不要**擅自改 SQL 重试超过一次。
3. 向用户汇报执行结果（表名、数据源、成功/失败详情）。

### Step 7 — 保留会话

保持标签页打开，供后续 skill 复用。

## 不变量

1. **执行前必确认**：粒度、数据源、SQL 关键内容经 AskUserQuestion 确认。
2. **SQL 透明**：执行前向用户展示表名与字段要点，不盲执行。
3. **失败即停**：报错原样报告，重试至多一次且需用户同意。
4. **删除红线**：任何「删除」入口（含删表类选项）一律不点击、不尝试。
5. **行动后验证**：以界面成功提示 + 佐证信号双确认，不以单一信号下结论。

## Notes / gotchas

- **建表是真实副作用**：平台数据源可能直连业务库，错数据源会建错库——
  数据源选择务必逐字核对名称。
- **右键菜单降级路线**见 Step 3。
- **树技术栈**：Element Plus el-tree，节点只显示名称。
- **ref 时效性（Trae）**：界面切换后旧 ref 失效，重新快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：持久化实体建表后，可用 `ynu-eos8-generate-page` 生成页面。
