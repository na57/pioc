# 显示系统表开关（EOS8 实体设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 实体设计器的**数据源**面板中，通过点击**数据源一级目录
（数据源类型）右边的图标**，切换是否展示系统表。

流程概览：
确认 IDE 已登录 → 确认期望方向（显示/隐藏）→ 打开实体设计器 →
点击数据源一级目录旁图标 → 验证系统表出现/消失。

**作用域铁律**：这是 toggle 操作，先向用户确认期望的**目标状态**
（要显示还是要隐藏），操作后必须验证状态与期望一致。

## When to use

- 用户说「显示系统表」「把系统表显出来」「隐藏系统表」。
- 数据源面板里找不到期望的表时，可主动建议用本 skill 排查
  （系统表被隐藏的情况）。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **目标状态**（必填）：`显示系统表` 或 `隐藏系统表`。
- **目标设计器**（按需）：在哪个构件包的实体设计器中操作。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 状态确认（AskUserQuestion，必经）

确认：「将把数据源面板的系统表切换为 <显示/隐藏>，是否继续？」

### Step 3 — 打开实体设计器，记录当前状态

1. 资源树双击实体集/实体打开实体设计器。
2. 定位**数据源**面板的一级目录（数据源类型）及其右侧图标。
3. **先判断当前状态**（toggle 重复点击会来回切）：
   观察一级目录下当前是否列出系统表（系统表通常有可识别的
   命名/图标；判断不了就问用户或截图佐证）。
   - 已是目标状态 → 无需操作，直接汇报；
   - 不是 → 继续点击。

### Step 4 — 点击切换图标

1. 点击数据源一级目录右侧的图标
   （图标可能极小且无文字，优先按结构定位：
   Trae 快照中找该目录节点的相邻图标 ref；WorkBuddy 按 DOM 结构定位）。
2. 图标不渲染或定位不到（Vue 条件渲染 `<!---->` 占位）：
   ① 重取快照重试一次；② 请用户手动点击，agent 接手验证。

### Step 5 — 验证

1. 重取快照/DOM：确认系统表出现（或消失），与目标状态一致。
2. 不一致 → 再点一次并复验（至多一次）；仍不对则如实报告。

### Step 6 — 保留会话

保持标签页与设计器打开，供后续 skill 复用。

## 不变量

1. **toggle 先判态**：操作前判断当前状态，已是目标状态就不点。
2. **行动后验证**：以面板中系统表的实际出现/消失为准。
3. **失败即停**：重试至多一次，之后转用户手动。
4. **删除红线**：数据源表 hover 出现的「删除」图标严禁点击
   （本 skill 不涉及，但操作中可能误触 hover）。

## Notes / gotchas

- **图标小而无文字**：按 DOM 结构/相邻关系定位，不要靠猜文本。
- **Vue 条件渲染**：控件可能不渲染（`<!---->` 占位），两次失败转用户手动。
- **ref 时效性（Trae）**：面板刷新后旧 ref 失效，重新快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：系统表显示后可用 `ynu-eos8-preview-table-data` 预览数据。
