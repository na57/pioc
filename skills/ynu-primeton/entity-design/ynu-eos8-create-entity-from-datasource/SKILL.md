# 从数据源创建实体（EOS8 实体设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 实体设计器中，把**数据源**面板里的表**拖拽**到画布，
系统自动生成对应实体。生成后可根据需求进一步配置。

与实体面板创建实体（`ynu-eos8-drag-create-entity`）的关键区别：
**使用数据源数据创建实体时，无需再次生成表**（表已存在）。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认源表与落点 → 打开实体设计器 →
拖拽表到画布 → 确认实体生成 → 按需配置 → 验证。

**作用域铁律**：源表与目标设计器必须经 `AskUserQuestion` 确认；
一次只处理用户确认的表，不批量拖别的表。

## When to use

- 用户想基于已有数据库表反向生成实体。
- 需要先看表里有什么数据时，先 `ynu-eos8-preview-table-data`。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **源表**（必填）：数据源面板中的表名。
- **目标设计器**（必填）：拖到哪个实体设计器画布（哪个构件包/实体集）。
- **实体命名**（按需）：生成后如需改名，按用户指定值。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将把数据源表 <表名> 拖入 <设计器> 画布生成实体，是否继续？」

### Step 3 — 打开实体设计器，定位源表

1. 资源树双击实体集/实体打开实体设计器。
2. 数据源面板展开定位目标表（看不到表时检查「显示系统表」开关
   ——`ynu-eos8-toggle-system-tables`——与面板折叠状态）。

### Step 4 — 拖拽表到画布

1. 执行拖拽：源 = 数据源面板中的表节点，目标 = 画布空白区域
   （Trae：Exec 内 `browser_drag`（若可用）或按下-移动-释放；
   WorkBuddy：对应拖拽工具）。
2. **拖拽可能不被画布识别**（HTML5 原生 drag & drop 对合成事件
   最敏感）：① 重取快照重试一次；② 改试「点选表 + 点画布」
   候选交互（若支持）；③ 请用户手动拖放，agent 接手后续配置。
3. ⚠️ 红线：hover 表出现的两个图标中，「删除」图标严禁点击。

### Step 5 — 确认实体生成并配置

1. 重取快照/DOM：画布中出现由该表生成的新实体。
2. 用户有命名要求 → 选中实体在属性区改名，改后复验。
3. 字段级定制交给 `ynu-eos8-edit-entity`。

### Step 6 — 验证

画布出现新实体且名称正确 → 汇报（含「该实体无需再生成表」提示）。

### Step 7 — 保留会话

保持标签页与设计器打开，供后续 skill 复用。

## 不变量

1. **拖拽前必确认**：源表与目标设计器经 AskUserQuestion 确认。
2. **行动后验证**：以画布出现新实体为准。
3. **失败即停**：拖拽两次失败转用户手动。
4. **删除红线**：任何「删除」入口（含 hover 出现的删除图标）
   严禁点击、不尝试。

## Notes / gotchas

- **HTML5 拖拽是最大风险点**：合成事件可能不触发 drop，及时转用户手动。
- **无需再生成表**：与实体面板创建的区别，向用户说明；
  但服务/引用/查询类配置不在本 skill 范围。
- **Vue 条件渲染**：hover 控件可能不渲染（`<!---->` 占位）。
- **ref 时效性（Trae）**：画布变化后旧 ref 失效，重新快照。
- **CDP 超时（仅 WorkBuddy）**：拖拽前 focus + sleep 约 2 秒。
- **衔接**：生成页面 `ynu-eos8-generate-page`。
