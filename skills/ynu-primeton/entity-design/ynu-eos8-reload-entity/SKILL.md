# 重新加载实体（EOS8 实体设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 实体设计器中，对实体执行**重新加载**，手动更新实体内容、
同步数据库中的实体数据（字段编辑与修改）。

**官方重要说明**：
- **只有持久化实体**可以通过重新加载同步数据库中的实体数据；
- 服务实体、引用实体、查询实体执行重新加载**不会**更新数据库数据；
- 数据库中**被删除的字段不会自动同步**到实体上；
  被删除的字段会变为**非持久化字段**。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认实体（并核对是否持久化实体）→
右键实体 → 菜单「重新加载」→ 验证。

## When to use

- 用户改了数据库表结构后想同步实体（加字段场景最典型）。
- 用户说「重新加载实体」「同步一下实体」。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **目标实体**（必填）：设计器画布/资源树中的实体名称。
- **预期变化**（按需）：用户期望同步到哪些字段（用于验证）。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

1. 确认目标实体与预期变化。
2. **先核对实体类型**：仅**持久化实体**重新加载有效；
   服务/引用/查询实体要向用户说明「重新加载不会同步数据库」，
   确认是否仍要执行。

### Step 3 — 打开实体设计器，定位实体

资源树双击实体集/实体打开实体设计器；
画布中定位目标实体节点。

### Step 4 — 右键实体，菜单选「重新加载」

1. 右键实体节点，期待操作菜单（含：删除、重新加载、生成页面、
   复制实体名称、查看表单等项）。
2. **右键可能无反应**：① 重取快照重试一次；② 键盘 ContextMenu 键；
   ③ hover 看操作图标；④ 请用户手动点出菜单后继续。
3. 菜单中选「重新加载」（Trae：`browser_click({ ref })`；
   WorkBuddy：`dom_cua_click`；无独立节点时键盘 `ArrowDown`+`Enter`）。
4. ⚠️ 红线：菜单中的「删除」项**严禁点击**（本 skill 不含删除）。

### Step 5 — 验证

1. 重取快照/DOM，核对实体字段：
   - 预期新增的字段出现 → 成功；
   - 预期变化未出现 → 如实报告；
   - **数据库中已删除的字段**：提醒用户它不会自动消失，
     会变为非持久化字段，是否处理由用户决定（本 skill 不做删除）。
2. 有报错 → 原样报告。

### Step 6 — 保留会话

保持标签页与设计器打开，供后续 skill 复用。

## 不变量

1. **类型先核对**：非持久化实体执行前必须说明无效风险并确认。
2. **行动后验证**：以实体字段实际变化为准。
3. **失败即停**：不重复触发重新加载超过一次。
4. **删除红线**：菜单「删除」项及任何删除入口严禁点击、不尝试。

## Notes / gotchas

- **删除字段不自动同步**：这是官方明确行为，验证时别把
  「字段还在」误判为失败。
- **右键菜单降级路线**见 Step 4。
- **ref 时效性（Trae）**：菜单/画布变化后旧 ref 失效，重新快照。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：字段增删改用 `ynu-eos8-edit-entity`；
  表结构变化用 `ynu-eos8-generate-table`（经确认）。
