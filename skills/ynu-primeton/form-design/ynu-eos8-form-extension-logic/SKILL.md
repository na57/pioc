# 表单扩展逻辑（EOS8 表单设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

为 EOS8 表单配置**扩展逻辑**。官方描述：表单扩展逻辑是在
**新增、修改、删除表单时触发**，调用 EOS 服务中的实体服务，
完成数据操作、远程调用等一系列场景的功能。
**与触发时机事件是同一事务，如果 EOS 服务调用失败，
那么整个触发时机事件都会回滚**。

本 skill 按文档聚合三部分：
1. **创建扩展逻辑 EOS 服务**（服务→实体服务→模板选择
   新增/修改/删除）；
2. **扩展逻辑 EOS 服务参数介绍**（双击空白面板打开
   逻辑流属性设置弹窗查看参数配置表；
   模版新增 / 模版修改 / 模版删除 三种模板参数说明）；
3. **场景绑定**（在表单设置→扩展逻辑中选择逻辑流绑定）。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认表单、逻辑类型
（新增/修改/删除）与逻辑流 → 创建实体服务 →
查看参数/调整逻辑流并保存 → 表单设置 → 扩展逻辑绑定 → 验证。

**作用域铁律**：仅在目标构件包的服务与目标表单内操作，
不碰无关逻辑流与资源。

## When to use

- 用户要在表单数据新增/修改/删除成功后触发服务端逻辑，
  例如：新增表单数据成功时发送信息通知给管理员。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **目标表单**（必填）：当前打开的表单设计器中的表单。
- **逻辑类型**（必填三选一）：`新增` / `修改` / `删除`
  （决定实体服务模板与表单侧绑定位）。
- **逻辑流名称**（必填）：要创建/绑定的实体服务（逻辑流）名。
- **远端调用**（按需）：场景需要时（如发短信）提供
  远程接口信息，用于 rest 图元配置。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将为表单 <表单名> 配置 <新增/修改/删除> 扩展逻辑，
创建实体服务 <逻辑流名> 并绑定，是否继续？」

### Step 3 — 创建扩展逻辑 EOS 服务

1. 打开构件包**服务**中的「实体服务」。
2. 右键创建一个实体服务（右键无反应时降级：
   ①重取快照重试→②键盘 ContextMenu 键→③请用户手动）。
3. 使用模板选择对应类型：
   逻辑类型为新增选「新增」模板；
   修改、删除的扩展逻辑选对应的「修改」「删除」模板。
4. ⚠️ 红线：此处「模版删除」仅是**模板类型选择**；
   界面上任何真正的「删除」按钮/菜单项严禁点击。

### Step 4 — 查看逻辑流参数（按需）

1. **双击逻辑流空白面板**，打开逻辑流属性设置弹窗，
   查看该逻辑流参数配置表中的参数详情。
2. 模板参数说明（官方文档）：
   - **模版新增**：此时 models 表单实体数据主键已经生成，
     可以获取 models 的主键数据；
   - **模版修改** / **模版删除**：参数配置表以弹窗
     实际展示为准，读出并汇报给用户。
3. 向用户汇报参数后关闭弹窗，**不做未确认的修改**。

### Step 5 — 调整逻辑流（按需，如远端调用场景）

1. 参考官方场景「在新增表单数据成功时发送信息通知给管理员」：
   调整逻辑流的图元，例如使用 **rest 图元**调用
   远程发送短信的接口。
2. 配置 rest 图元（接口地址、参数从逻辑流参数取）。
3. **保存**逻辑流。
4. 验证：逻辑流保存成功提示出现。

### Step 6 — 表单侧绑定扩展逻辑

1. 回到表单页面，点击顶部「表单设置」→
   切换到「**扩展逻辑**」页签。
2. 在对应类型的扩展逻辑位中选择刚创建的逻辑流：
   新增数据扩展逻辑 / 修改 / 删除（与逻辑类型一致）。
3. 保存绑定。
4. 验证：绑定下拉回读显示所选逻辑流。

### Step 7 — 验证与收尾

1. **行动后验证**：以绑定回读 + 逻辑流保存状态为准；
   运行效果（如通知发出）依赖实际触发，只读验证，
   不代用户制造业务数据。
2. 保持设计器/服务页打开，供后续复用。

## 不变量

1. **绑定前必确认**：逻辑类型、逻辑流名经 AskUserQuestion 确认。
2. **同一事务风险告知**：EOS 服务调用失败会导致
   整个触发时机事件回滚，向用户说明此约束。
3. **行动后验证**：以绑定与保存实际状态为准，
   不以点击成功为准。
4. **失败即停**：同一操作两次失败即停下汇报。
5. **删除红线**：任何「删除」按钮/图标/菜单项严禁点击；
   「模版删除」仅可作为模板类型选项被选择，
   绝不执行删除动作。

## Notes / gotchas

- **流程表单不生效（文档明确）**：扩展逻辑在流程表单中
  不生效，流程表单中请使用**流程业务事件**。
  目标是流程表单时直接停下说明。
- **模板与触发时机一一对应**：新增触发选新增模板、
  修改选修改模板、删除选删除模板，选错则参数不匹配。
- **模版新增可取主键**：models 主键在服务内已生成，
  可直接获取主键数据用于后续图元。
- **参数查看入口**：双击逻辑流**空白面板**（非图元）
  才弹出逻辑流属性设置。
- **ref 时效性（Trae）**：打开弹窗/切换页面后旧 ref 失效，重新取。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **衔接**：表单内数据联动用业务规则
  （`ynu-eos8-form-business-rules`）；服务端事务性动作
  才用本 skill。
