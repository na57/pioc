# 代码模式（EOS8 表单设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 表单设计器中使用**代码模式**。
官方描述：允许用户将视图切换到代码模式，在代码模式下，用户可以自由地编写 Vue 模版，**但表单设计器将被禁用**。在 template 编辑器中自由编写代码，**保存即生效**。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认目标表单与代码内容（代码必须经用户确认）→ 切换代码模式 → 在 template 编辑器写入代码 → 保存 → 验证效果并汇报。

**代码红线（本 skill 核心安全约束）**：本 skill **不代用户随手写逻辑**；
要写入编辑器的每一段代码都必须先完整展示给用户，
经用户确认后才写入。

**作用域铁律**：仅在当前已打开的表单设计器内操作，不碰无关表单与资源。

## When to use

- 用户想把表单视图切到代码模式，直接编写 Vue 模版。
- 可视化设计器实现不了的效果，用户要求用代码方式实现。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **目标表单**（必填）：在哪个表单设计器中切换代码模式。
- **要写入的代码**（必填）：写入 template 的 Vue 模版代码；
  用户只给需求不给代码时，起草后必须先给用户确认，不要直接写入。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域与代码确认（AskUserQuestion，必经）

1. 确认：「将在表单 <表单名> 中切换到代码模式并写入以下代码，是否继续？」附完整代码。
2. 明确告知：代码模式下**表单设计器将被禁用**；保存即生效。
3. 用户未确认代码前，不进入编辑器写入环节。

### Step 3 — 切换到代码模式

1. 在表单设计器中找到视图切换入口，切换到**代码模式**
  （入口具体形态以界面为准，见 gotchas）。
2. 验证：已呈现 template 编辑界面，设计器已禁用。

### Step 4 — 编写代码并保存

1. 在 template 编辑器中写入经用户确认的代码
  （Trae：Exec 内输入；WorkBuddy：对应输入方式）。
2. 触发**保存**。
3. 验证：保存成功提示出现；如可预览，预览核对效果。
4. 读回编辑器内容与确认稿比对，不一致先修正再保存。

### Step 5 — 汇报

汇报已写入的代码内容、保存结果、预览/验证情况；
提醒如需回到可视化设计，需切回设计模式。

## 不变量

1. **代码确认红线**：写入编辑器的代码必须先经用户确认，严禁代用户随手写逻辑。
2. **行动后验证**：以保存成功与预览实际效果为准，不以输入成功为准。
3. **失败即停**：切换入口找不到或写入两次失败即停，转用户手动。
4. **作用域铁律**：只在当前表单的代码编辑器内改动，不碰其他表单与资源。

## Notes / gotchas

- **设计器禁用**：代码模式下可视化设计器被禁用，写码前确认用户接受这一点。
- **保存即生效**：没有草稿确认环节，错误代码保存后立即影响表单，务必先确认再保存。
- **代码编辑器输入风险**：编辑器可能有自动补全/格式化，粘贴或键入后读回比对，不一致先修正。
- **ref 时效性（Trae）**：快照变化后旧 ref 失效，重新取。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **细节待人工核对**：文档未给出切换代码模式的具体入口形态（按钮/下拉/图标位置），执行时以实际界面为准。
