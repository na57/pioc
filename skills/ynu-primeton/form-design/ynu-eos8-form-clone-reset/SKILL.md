# 表单克隆与重置（EOS8 表单设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 表单设计器的**表单状态**管理界面中执行
**克隆状态**与**重置状态**两项操作。

背景（官方描述）：可配置表单中每一项组件状态
（读写、只读、禁用、隐藏）。初始化默认
**【新增】、【编辑】、【查看】**三种表单状态。
表单状态是所有组件状态的集合；使用一个表单时
必须要指定一个表单状态。使用一个表单时，必须要指定一个表单状态，没有状态的表单是没有意义的。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认表单与操作 →
定位状态列表 → 克隆（选定状态 → 点「克隆当前状态」→
调整新状态组件状态）或重置（二次确认 → 点「重置」）→
以状态列表实际变化验证。

**作用域铁律**：仅在当前已打开的表单设计器内操作，
不碰无关表单与资源；克隆/重置前必须经 `AskUserQuestion` 确认。

**删除红线（本 skill 核心安全约束）**：文档提及「删除状态」
（初始化的【新增】、【编辑】、【查看】三种状态默认不可删除），
但本 skill **严禁点击任何「删除」按钮/图标/菜单项**。
用户要求删除状态时，告知此 skill 不执行删除，请用户手动操作。

## When to use

- 用户想基于某个现有状态复制出新的自定义表单状态。
- 用户想把表单状态恢复为初始化的【新增】【编辑】【查看】。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **目标表单**（必填）：当前打开的表单设计器中的表单。
- **操作**（必填二选一）：`克隆` 或 `重置`。
- **克隆源状态**（克隆时必填）：已存在的状态名
  （如【新增】【编辑】【查看】或自定义状态）。
- **新状态调整**（按需）：克隆后是否修改新状态下
  某些组件的状态（读写/只读/禁用/隐藏）。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

- 克隆：「将在表单 <表单名> 中，克隆状态 <源状态名>
  生成新状态，是否继续？」
- 重置：「重置将清空 <表单名> 的自定义状态、
  恢复为初始化的【新增】【编辑】【查看】三种状态，
  **不可撤销**，是否继续？」

### Step 3 — 定位表单状态管理界面

1. 在表单设计器中定位表单状态管理界面（状态列表，
   展示初始化及自定义状态，可配置各组件读写/只读/
   禁用/隐藏状态）。
2. 重取快照读出状态列表，向用户汇报现有状态名。

### Step 4A — 克隆状态

1. 在状态列表中**选定某个已存在的状态**
   （用户指定的克隆源状态）。
2. 点击「**克隆当前状态**」按钮。
3. 得到与该状态权限配置相同的一个新状态。
4. 若用户要求调整：在新状态下修改指定组件的状态
   （读写/只读/禁用/隐藏），逐项修改后回读确认。
5. 验证：状态列表中出现新状态，且组件状态配置与
   预期一致（重取快照回读）。

### Step 4B — 重置状态

1. **二次确认已完成**（Step 2），未确认不得点击重置。
2. 点击「**重置**」按钮，等待状态列表刷新。
3. 验证：状态列表恢复为初始化的【新增】【编辑】【查看】
   三种状态（重取快照回读）。
4. 重置后向用户汇报：哪些自定义状态已不存在，
   组件状态回到初始化默认（新增/编辑默认「读写」，
   查看默认「禁用/只读」）。

### Step 5 — 收尾

1. 不碰状态列表以外的任何界面元素。
2. 保持设计器打开，供后续 skill 复用。

## 不变量

1. **重置前必须二次确认**：重置属破坏性操作
   （清空自定义状态），AskUserQuestion 确认后才执行；
   重置 ≠ 删除，用户明确要求时可以执行。
2. **删除红线**：任何「删除」按钮/图标/菜单项
   （含「删除状态」）严禁点击、严禁尝试。
3. **行动后验证**：以状态列表回读结果为准，
   不以按钮点击成功为准。
4. **失败即停**：同一操作两次失败即停下汇报。

## Notes / gotchas

- **初始化三状态不可删除**：文档明确【新增】【编辑】【查看】
  默认不可删除；即使面对自定义状态，本 skill 也不做删除。
- **重置不可撤销**：执行前务必让用户明确知晓会
  丢失全部自定义状态配置。
- **表单必须指定状态**：新建克隆状态后提醒用户
  在使用表单时指定状态，否则表单无意义。
- **克隆后默认同权限**：克隆出的新状态与源状态
  组件状态完全相同，需按需逐项调整。
- **ref 时效性（Trae）**：状态列表刷新后旧 ref 失效，重新取。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **API 设置组件状态（背景知识）**：运行时可用
  `this.Api.setVisible/setReadonly/setDisabled(true/false, ['field'])`
  单独控制组件状态，与设计器状态配置互补；
  细节待人工核对可参考官方「表单状态」文档。
