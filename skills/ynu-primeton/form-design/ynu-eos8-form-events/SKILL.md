# 表单事件（EOS8 表单设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 表单设计器中配置**表单事件**。
官方描述：事件类型为事件的触发时机或条件；可以选择相应的事件添加代码触发。
入口：**表单设置 ⇒ 高级设置 ⇒ 事件**。

本 skill 为聚合型，覆盖 **9 种事件类型**（执行时按用户指定的事件类型走对应小节即可，不要求每次全跑）：

| # | 事件类型 | 适用时机/用途 | 关键约束 |
|---|---------|--------------|---------|
| 1 | 表单加载前 | 初始化表单数据、变量赋值 | 编辑/查看时 `formData` 还没查询出来 |
| 2 | 表单查询前 | 查看/编辑状态下，查询详情数据之前修改查询条件 | 仅查看/编辑状态 |
| 3 | 表单查询后 | 查看/编辑状态下，查询详情数据之后修改查询结果 | 仅查看/编辑状态 |
| 4 | 表单加载后 | 页面元素已渲染，获取页面元素及元素方法、设置组件隐藏/禁用；可直接取 `formData` | 此时 `formData` 已查出 |
| 5 | 表单提交前 | 修改提交数据 `formData`；校验不满足可 `return false` 取消提交 | 返回 `false` 即取消提交 |
| 6 | 表单提交成功后 | 提示信息等后续处理 | 此时 `formData` 主键已生成 |
| 7 | 流程提交前 | 动态修改流程审批页面的提交配置与抄送配置（可用参数 `processContext`、`bfpContext`）；在所有配置中优先级最高 | 仅流程表单 |
| 8 | 表单打印前 | 自定义返回数据供打印模板取用 | 配合模板字段 |
| 9 | 表单打印后 | 用原生 JS 调整打印页面样式 | 打印地址追加 `&isDebug=true` 便于调试 |

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认目标表单、事件类型与代码（代码必须经用户确认）→
高级设置事件区新增对应事件 → 写入代码保存 → 以运行时实际效果验证汇报。

**删除红线（本 skill 核心安全约束）**：事件列表旁可能出现
「删除」图标——本 skill **严禁点击任何删除图标**，
删除/停用事件一律由用户手动决定。

**作用域铁律**：仅在当前已打开的表单设计器内操作，不碰无关表单与资源。

## When to use

- 用户想在表单生命周期的某个时机执行自定义代码（初始化、校验、改数据、改流程配置、打印定制等）。
- 用户想给流程表单动态配置参与者与抄送。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **目标表单**（必填）：在哪个表单设计器中操作。
- **事件类型**（必填）：上表 9 种之一。
- **事件代码**（必填）：要写入的 JS 代码；用户只给需求时，起草后必须先给用户确认。
- **相关字段/组件/环节 id**（按需）：如校验字段、流程活动定义 id 等。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域与代码确认（AskUserQuestion，必经）

1. 确认：「将在表单 <表单名> 的高级设置事件区新增 <事件类型> 事件，写入以下代码，是否继续？」附完整代码。
2. 同时说明所选事件类型的适用时机与约束（见 Overview 表格），避免选错事件。

### Step 3 — 打开事件区并新增事件

1. 点击**表单设置** → **高级设置** → 定位**事件**区。
2. 选择事件类型（9 种之一），点击新增。
3. 在代码编辑器中写入经用户确认的代码并保存。
4. 验证：事件出现在事件列表中，代码与确认稿一致。

### Step 4 — 各事件类型的专项验证（按所选事件执行）

1. **表单加载前**：打开表单（新增/编辑），核对初始化赋值生效
   （官方示例：`this.formData.pid = "21"` 让选人组件按人员 id 回显；
   也可调用后端接口取数为组件绑定的字段赋值）。
2. **表单查询前/后**：以查看/编辑状态打开表单，核对查询条件/结果被按预期修改。
3. **表单加载后**：打开表单，核对页面元素操作生效（隐藏/禁用等）。
4. **表单提交前**：
   - 修改数据场景：提交后列表/详情中字段值符合赋值预期
     （官方示例：`this.formData.status = "applying"`，可在视图显示字段中
     添加状态列并绑定字典格式化核对）。
   - 取消提交场景：触发校验不通过时出现提示
     （如 `this.$message.error('...')`）且未发生保存。
5. **表单提交成功后**：提交成功后提示等后续动作发生（主键已生成）。
6. **流程提交前**：走流程提交，核对提交弹框按事件返回的配置显示
   （是否指定活动环节、是否单选、是否显示审批意见、允许修改分支环节/参与者、
   `links` 后续环节配置、`sendRules` 抄送配置）；
   活动定义 id 可在流程设计页面找到。
7. **表单打印前**：执行打印，核对 excel 模板取到自定义返回数据
   （`const data = arguments[0]; return {...}`，模板中以 `$` 取用）。
8. **表单打印后**：打印地址追加 `&isDebug=true` 打开打印后页面，
   核对原生 JS 样式调整生效（官方示例：
   `document.querySelector('.body-content tr:nth-of-type(1)').style.display = 'none'`）。

### Step 5 — 汇报

汇报新增的事件类型与代码、验证方式与结果；
如验证依赖运行时操作（提交/流程/打印），说明需用户配合的步骤。

## 不变量

1. **代码确认红线**：写入事件的代码必须先经用户确认，严禁代用户随手写逻辑。
2. **删除红线**：事件列表旁的「删除」图标严禁点击。
3. **行动后验证**：以运行时实际效果为准，不以保存成功为准。
4. **失败即停**：入口找不到或写入两次失败即停，向用户汇报现状。
5. **作用域铁律**：只新增用户指定的事件，不改、不删其他事件。

## Notes / gotchas

- **选对事件时机**：加载前 `formData` 尚未查出（不要在此读表单数据）；
  加载后才有页面元素；提交前可改数据或 `return false` 取消；提交成功后主键才生成。
- **流程提交前优先级最高**：其配置覆盖提交按钮的提交策略和抄送配置；
  未添加该事件时，提交弹框按提交按钮的提交策略和抄送配置显示。
- **return false 即取消提交**：取消提交类事件必须返回 `false` 并给出提示，否则用户无感知。
- **代码编辑器输入风险**：编辑器可能有自动补全/格式化，写入后读回与确认稿比对，不一致先修正再保存。
- **ref 时效性（Trae）**：快照变化后旧 ref 失效，重新取。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **验证依赖运行时**：提交/流程/打印类事件的验证需实际触发对应动作，
  注意不要在真实业务数据上做破坏性提交（必要时用测试数据）。
