# 表单按钮设置（EOS8 表单设计器，WorkBuddy / Trae 双运行时兼容）

## Overview

在 EOS8 表单设计器中配置**表单底部操作按钮**。
官方描述：按钮设置区的按钮有**系统按钮**和**自定义按钮**，
可以自定义按钮样式和处理逻辑；按钮会在**编辑或查看**
表单时候显示。

系统按钮共 6 个（官方动作说明）：
- **取消**：不对表单内容进行改变，关闭表单窗口；
- **打印**：打印当前表单内容，可选择模版类型，
  只在表单查看状态下显示；
- **下载pdf**：将当前表单内容下载成 pdf 文件，
  只在表单查看状态下显示，同打印一样；
- **重置**：使表单控件内容清空（若控件有默认值设置，
  重置后会显示设置的默认值）；
- **保存**：保存表单内容持久化入库，然后关闭当前表单窗口；
- **保存并继续**：保存入库后重置表单内容，可继续新增。

本 skill 按文档聚合：**系统按钮说明**、
**自定义按钮 / 编辑按钮**、**场景（保存并继续下拉不刷新）**。

流程概览：
确认 IDE 已登录 → AskUserQuestion 确认表单与按钮操作 →
表单设置 → 按钮设置 → 查询/添加/编辑按钮 →
调试预览验证效果。

**作用域铁律**：仅在当前已打开的表单设计器内操作，
只改用户确认过的按钮，不碰其他按钮与配置。

## When to use

- 用户想了解表单有哪些系统按钮及其行为。
- 用户想添加自定义按钮（设置文字、样式、点击动作、状态控制）。
- 用户想编辑现有按钮的文字/样式/动作/状态控制。

## Step 0 — 运行时探测（必须最先执行）

- 工具列表含 `mcp__browser__browsers_list` → **WorkBuddy 模式**。
- 工具列表含 integrated_code_mode 的 `Exec`（`await tools.browser_*`）→ **Trae 模式**。
- 两者都没有 → 提示用户启用对应浏览器扩展，终止流程。

## 参数

- **目标表单**（必填）：当前打开的表单设计器中的表单。
- **操作**（必填三选一）：`查看系统按钮` / `添加自定义按钮` /
  `编辑按钮`（需指定按钮名）。
- **按钮配置**（按需）：按钮文字、样式、点击动作
  （动作代码或选项）、状态控制。

缺参数 → `AskUserQuestion` 询问，不要猜。

## Workflow

### Step 1 — 确认 IDE 已打开且已登录

复用 `ynu-lowcode-login` 等产出的 IDE 标签页/viewId；
未登录先执行 `ynu-lowcode-login`。

### Step 2 — 作用域确认（AskUserQuestion，必经）

确认：「将在表单 <表单名> 中 <查看系统按钮 /
添加自定义按钮 / 编辑按钮 <按钮名>>，是否继续？」
编辑系统按钮时额外确认：「添加自定义动作代码后，
该系统按钮将**不再执行原本逻辑**（如保存按钮将不再
自动入库），是否继续？」

### Step 3 — 打开按钮设置

1. 点击顶部「表单设置」→ 切换到「**按钮设置**」页签。
2. 重取快照读出当前按钮列表（系统按钮 + 已有自定义按钮），
   向用户汇报。

### Step 4A — 查看系统按钮

1. 读出按钮区现有按钮，对照官方 6 个系统按钮
  （取消、打印、下载pdf、重置、保存并继续、保存）
   说明各自的动作（见 Overview）。
2. 提示显示条件：打印、下载pdf 只在**表单查看状态**下显示。
3. 仅查询汇报，不做修改。

### Step 4B — 添加自定义按钮

1. 在按钮设置区选择添加自定义按钮。
2. 编辑按钮：设置**按钮文字**、**样式**、
   **点击时触发的动作**、**状态控制**。
3. 动作代码经用户确认后写入（Trae：编辑器逐段输入后
   回读校验；WorkBuddy：逐字段填写）。
4. 保存按钮配置。
5. 验证：按钮列表出现新按钮，配置回读一致。

### Step 4C — 编辑现有按钮

1. 选中目标按钮进入编辑：可设置文字、样式、
   点击时触发的动作和状态控制等。
2. ⚠️ **系统逻辑覆盖警示（文档明确）**：编辑**系统按钮**
   时若添加自定义动作代码，该系统按钮将按照自定义的
   动作代码执行，**不会再执行原本的逻辑**——
   必须经 Step 2 二次确认后才写入动作代码。
3. 保存后验证：按钮配置回读一致。

### Step 5 — 调试预览验证

1. 通过「调试预览」查看按钮显示与点击效果
   （新增/编辑/查看状态下的按钮呈现差异）。
2. **行动后验证**：以预览中按钮实际显示与行为为准，
   不以保存成功为准。
3. 效果不符 → 原样汇报，不再盲目改动。

## 不变量

1. **写前必确认**：新增按钮、编辑按钮、动作代码
   内容均经 AskUserQuestion 确认。
2. **系统逻辑覆盖须二次确认**：给系统按钮加动作代码
   前必须让用户明确知晓会覆盖原本逻辑。
3. **行动后验证**：以调试预览实际效果为准。
4. **失败即停**：同一操作两次失败即停下汇报。
5. **删除红线**：按钮设置界面任何「删除」按钮/图标/
   菜单项严禁点击；不删除既有按钮（如用户要求删除，
   请用户手动操作）。

## Notes / gotchas

- **系统逻辑覆盖是双向的**：自定义动作会整体替换
  系统按钮原本逻辑；若既要原本逻辑又要附加动作，
  需在代码中显式调用原 API（见下一条）。
- **「保存并继续」下拉不刷新（官方场景）**：表单下拉控件
  绑定实体/接口数据时，点「保存并继续」后选项不含刚保存的值。
  官方解法：在「保存并继续」按钮加动作代码，
  先执行原本方法再刷新表单或重查接口：
  ```javascript
  // 绑定实体数据源：执行原本保存并继续后强制刷新表单
  await this.Api.submitFormAndGoOn()
  setTimeout(() => {
    this.getLoading = true
    setTimeout(() => { this.getLoading = false }, 500)
  }, 500)

  // 绑定自定义变量 v_list：执行原本方法后重新查接口赋值
  // 步骤1 定义方法 getOptionList：Ajax.post 查询后
  //   this.Api.getElement('pid').setOptions(this.v_list)
  // 步骤2 按钮动作代码：
  await this.Api.submitFormAndGoOn()
  setTimeout(() => { this.getOptionList() }, 500)
  ```
- **打印/下载pdf 仅查看状态显示**：预览看不到时
  先确认当前表单状态。
- **重置按钮语义**：清空控件内容但有默认值的控件
  会回到默认值——向用户解释时勿说成"清空一切"。
- **ref 时效性（Trae）**：切换页签/保存后快照变化，旧 ref 失效，重新取。
- **CDP 超时（仅 WorkBuddy）**：点击前 focus + sleep 约 2 秒。
- **Vue 条件渲染**：hover 出现的编辑图标若以 `<!---->`
  占位不渲染，两次失败转用户手动。
- **衔接**：按钮动作里可配合业务规则
  （`ynu-eos8-form-business-rules`）与扩展逻辑
  （`ynu-eos8-form-extension-logic`）使用。
